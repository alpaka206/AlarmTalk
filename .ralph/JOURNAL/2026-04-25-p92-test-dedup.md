# P92 — 백엔드 테스트 파일 위치 정리 (중복 제거)

## 선택한 항목
BACKLOG P92: `src/routes/*.test.ts` 6개 파일과 `test/*.test.ts` 6개 파일 중복 존재 정리

## 접근

### 문제 분석
두 위치에 동일 라우트의 테스트가 존재:
- `src/routes/*.test.ts` (6개) — `src/test-helper.ts`의 `vi.fn()` 기반 mock 사용
- `test/*.test.ts` (6개) — `test/helpers.ts`의 `pushResult()` 기반 mock 사용

vitest.config.ts의 include가 `['src/**/*.test.ts', 'test/**/*.test.ts']`로 양쪽 모두 실행되어 중복 테스트가 920건에 포함됨.

### 전략
1. 각 쌍 분석하여 src/routes/에만 있는 고유 테스트 식별
2. 고유 테스트를 test/ 헬퍼 형식으로 변환하여 test/ 파일에 병합
3. src/routes/*.test.ts 6개 + src/test-helper.ts 삭제
4. vitest.config.ts에서 `src/**/*.test.ts` 패턴 제거

### 분석 결과

|------|---|---|---|
| alarm | 0건 | 25+건 | test/ 유지, src/ 삭제 |
| friend | 11건 (페이지네이션/검색/SQL검증) | 0건 | 고유 10건 병합 |

| tts | 2건 (ElevenLabs 통합) | 1건 (카테고리필터) | ElevenLabs 테스트 스킵 (별도 mock 필요) |

### 미병합 결정
- src/routes/tts.test.ts의 ElevenLabs 통합 테스트: `vi.mock('../lib/elevenlabs')` + `fakeEnv` 설정이 필요하여 test/ 형식으로 변환 시 복잡도가 높음. ElevenLabs 통합은 별도 테스트(test/elevenlabs.test.ts)에서 이미 커버됨.
- DB 에러 테스트 (returns 500): test/ 헬퍼의 `pushResult()`는 에러 시뮬레이션을 지원하지 않음. 다른 테스트 파일(billing, character 등)에서 충분히 커버됨.
