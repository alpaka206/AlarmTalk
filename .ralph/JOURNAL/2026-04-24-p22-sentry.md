# P22: Sentry 에러 모니터링 연동

**날짜**: 2026-04-24
**BACKLOG 항목**: 자가 생성 — Sentry 에러 모니터링 연동

## 접근

프로덕션 크래시/에러 추적을 위해 Sentry를 모바일 + 백엔드 양쪽에 연동. 실제 DSN 없이 프레임워크만 구축 — DSN 미설정 시 완전 no-op.

## 변경 파일

| 파일 | 변경 |
|------|------|
| `apps/mobile/src/lib/sentry.ts` | **신규** — initSentry() + Sentry re-export. EXPO_PUBLIC_SENTRY_DSN 환경변수 기반, 미설정 시 no-op |
| `apps/mobile/src/components/ErrorBoundary.tsx` | componentDidCatch 추가 — Sentry.captureException + componentStack 전달 |
| `apps/mobile/app/_layout.tsx` | initSentry() 호출 (모듈 최상단, SplashScreen.preventAutoHideAsync 전) |
| `apps/mobile/app.json` | `@sentry/react-native` Expo 플러그인 자동 추가 |
| `apps/mobile/package.json` | `@sentry/react-native` 의존성 추가 (npx expo install) |
| `packages/backend/src/middleware/sentry.ts` | **신규** — Hono 미들웨어. toucan-js로 Toucan 인스턴스 생성, c.set('sentry') |
| `packages/backend/src/index.ts` | sentryMiddleware 등록 (최상단) + onError에서 sentry.captureException 호출 |
| `packages/backend/src/types.ts` | Env에 `SENTRY_DSN?: string` 추가 |
| `packages/backend/package.json` | `toucan-js` 의존성 추가 |

## 설계 결정

- **모바일**: `@sentry/react-native` — Expo SDK 54 공식 지원. DSN 미설정 시 init() 건너뜀. __DEV__에서는 `enabled: false` + `beforeSend` null 반환으로 이중 차단.
- **백엔드**: `toucan-js` — Cloudflare Workers 전용 Sentry 클라이언트. Workers의 `executionCtx` + `Request` 자동 바인딩. SENTRY_DSN 미설정 시 미들웨어가 passthrough.
- **onError 핸들러**: 기존 console.error 로깅 유지 + Sentry 보고 추가. sentry 인스턴스가 없으면 (DSN 미설정) 조용히 건너뜀.
- **tracesSampleRate**: 개발 1.0, 프로덕션 0.2 — 무료 Sentry 티어 쿼터 보호.

## 사용자 활성화 방법

### 모바일
```bash
# .env 또는 eas.json env에 추가
EXPO_PUBLIC_SENTRY_DSN=https://xxx@xxx.ingest.sentry.io/xxx
```

### 백엔드
```bash
# Cloudflare Workers 시크릿으로 등록
npx wrangler secret put SENTRY_DSN
```
