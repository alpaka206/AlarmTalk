## 1) 한 줄 결론

**세 질문에 각각: ① 옛 코드를 토대로 이어간다(단 네트워크 계층은 버리고 다시 쓴다) ② Swift 6 + SwiftUI 그대로, KMP·크로스플랫폼 전부 제외 ③ 지금은 착수하지 않는다 — 지금 할 일은 반나절짜리 실기기 Go/No-Go 스파이크 하나뿐이다.**

이유 한 문장: 34k줄 중 진짜 값어치인 AlarmKit 운용 지식·현지화·테스트는 백엔드 계약 표류와 무관하게 그대로 살아 있어 새로 짜면 손해지만, 그 코드의 **핵심 전제(`Library/Sounds` 커스텀 사운드)가 Apple이 "known issue"라고 답한 경로**이고 한 번도 컴파일된 적이 없어, 검증 전에 착수하는 건 도박이다.

## 2) 근거 (수치·사실만)

**가장 중요한 발견 — 두 조사가 정면으로 충돌한다.**

- 옛 iOS는 App Group의 오디오를 `Library/Sounds/voice-<key>.<ext>` 로 복사·트랜스코드한 뒤 `AlertConfiguration.AlertSound.named(_)` 로 넘긴다(`AlarmSoundStaging.swift`, `AlarmSoundResolver.swift`). 이게 "앱이 죽어도 잠금화면에서 내 사람 목소리가 울린다"의 전부다.
- 그런데 Apple 엔지니어가 2025-09 "`Library/Sounds` 폴백은 알려진 이슈"라고 답했고, [thread 798140](https://developer.apple.com/forums/thread/798140)의 **2026-02 최신 댓글이 "변한 게 없다"**(`.wav`로 바꿔도 동일).
- 옛 코드는 **한 번도 컴파일·실행된 적이 없다**(README: "not built in this Windows workspace"). 즉 이 앱의 단일 최대 자산이 **미검증 + 공개적으로 깨진 것으로 보고된 경로 위에 서 있다.**

**계약 표류 규모 (2026-07-21 → HEAD, 403 커밋)**

- 라우트 파일 7개 통삭제(library/friend/gift/stats/family-invite/alarm-source/billing-apple), 개별 엔드포인트 12개 삭제·변경.
- 마이그레이션 78~93 (16개 추가). 그중 **#88이 `push_tokens.platform` CHECK에서 `'ios'` 를 제거**했다 — 확인함(`migrations.ts:1852` → `CHECK(platform IN ('android','web'))`). **DB가 iOS 푸시 토큰을 거절한다.**
- `store_transactions.provider` = `CHECK(provider = 'google')`. `users.apple_id`·`subscriptions.apple_*` 3컬럼 DROP(#82).
- `app-version.ts:48` 확인함 — `appVersionPolicy(_platform)` 이 **어떤 값이 와도 Android 정책(min 21 / latest 23)** 을 돌려준다. iOS 빌드번호는 즉시 강제 업데이트 차단에 걸린다.
- P0(안 고치면 앱이 아예 안 돎) 8건, P1(화면·데이터가 깨짐) 15건.

**되살리기 비용의 진짜 정체 — 코드가 아니라 법무**

- Apple 로그인·결제가 코드·스키마·법무문서 **3중으로** 제거됨. 개인정보처리방침 v4(2026-07-30)에 "Google Play 단일 결제"가 **명시**돼 있다.
- 되살리면 문서 개정 → `CURRENT_POLICY_VERSION` 4→5 → **전원 재동의**. 이 마찰이 **iOS와 무관한 안드로이드 베타 사용자에게 그대로 튄다.**
- App Store 심사는 소셜 로그인이 있으면 Sign in with Apple을 **요구**한다. 선택이 아니다.

**공유 코어는 사실상 없다**

- 안드 37,843줄 중 즉시 이식 가능 순수 로직 **681줄(1.8%)**, 리팩터링 포함 상한 **~1,300줄(3.5%)**.
- KMP로 그 1,300줄을 얻으려면 **4,286줄+**(Retrofit→Ktor 1,583 / Room→SQLDelight 982 / AlarmRepository 분해 1,721)를 건드린다. **3.3배 역전**, 그것도 출시 직후 안드로이드의 네트워크·DB를 전면 교체하면서.
- `packages/shared` 는 3파일 153줄이고 백엔드조차 24개 라우트 중 3개만 import한다. 공유할 "계약"이 거기 없다.

**복원 경로**: `9f427c69`(189파일 48,910줄 삭제) 확인함. 데스크톱 사본은 CRLF 정규화 후 바이트 동일 → **`git revert 9f427c69` 를 쓴다.** 사본 복사는 이력이 끊긴다.

## 3) 언어/스택 권고

**Swift 6 + SwiftUI + XcodeGen, SPM 의존성 0개 유지. 옛 `project.yml` 그대로.**

- 이 앱의 정체성(정시 울림·잠금화면 점유·오디오 소유)은 **전부 OS API 표면**이다. 어떤 추상화도 이걸 줄여주지 않는다.
- 외부 라이브러리 0개는 1인 개발에서 가장 큰 자산이다. 공급망·버전충돌·`pod install` 지옥이 없다. 이걸 깨지 말 것.
- Swift 6 strict concurrency를 옛 코드가 이미 지키고 있다(`@MainActor` 격리, `nonisolated` region 회피, `@unchecked Sendable` 근거 주석). 낮추지 말고 그대로 간다 — 알람 앱에서 인터리브 버그는 "안 울림"으로 나타난다.

**KMP를 빼는 이유** — 위 3.3배 역전이 전부다. 1,300줄 얻자고 작동 중인 안드로이드 네트워크·DB를 갈아엎는다. 그리고 KMP를 넣어도 SwiftUI 화면 전량, AlarmKit 스케줄링, StoreKit2, APNs, 문자열 896×3은 **여전히 새로 써야 한다.** 이 앱에서 KMP가 해주는 일은 실질적으로 0이다.

**Flutter/RN을 빼는 이유** — `alarm/`+`ringing/`+`sync/` 2,938줄이 전부 플랫폼 채널 네이티브로 다시 나온다. 네이티브 코드가 사라지는 게 아니라 Dart 레이어가 **추가**된다. 안드로이드를 버리든가 앱 2개를 유지해야 한다.

**공유 코어 대신 할 것**: `packages/shared` 153줄은 **손으로 Swift에 옮긴다**(반나절). 안드로이드가 이미 그렇게 하고 있으니 방식이 늘지 않고, `String`이 grapheme 단위인 Swift에선 서러게이트 절단 문제가 오히려 더 안전해진다.

## 4) 알람 발사 설계

**대전제: iOS엔 발사 시점 코드 실행이 없다.** AlarmKit은 **해제 시점**에만 `stopIntent`가 돈다. 안드로이드가 `RingingService.kt:325`에서 **울릴 때** 하던 유료 권한 재확인·버킷 회전·문구 갱신을 **전부 예약/갱신 시점으로 옮겨야 한다.** "푸시가 유실돼도 울림 시점 게이트가 막아준다"는 안전망이 iOS엔 없다.

### 2안을 먼저 만들고, 1안을 그 위에 얹는다 (순서가 중요하다)

옛 코드는 1안을 기본으로 짜고 2안을 폴백으로 뒀다. **거꾸로 가야 한다.** 2안은 1안이 되든 안 되든 **30초 초과·트랜스코드 실패·staging 실패에서 항상 필요**하고, 1안은 Apple이 언제 고칠지 모르는 남의 일정에 묶여 있다.

**2안(기본선) — 번들 스톡클립 + 해제 후 개인 목소리**

- **무료/시스템 목소리**: `lib/stock-clips.ts`의 144클립(~30MB)을 **앱 번들에 동봉**. 번들 경로는 동작이 확인된 경로다 → 무료 티어는 안드로이드와 **동일하게** "그 사람 목소리로 깨어난다"가 성립한다.
- **클론/공유받은 개인 목소리**: AlarmKit은 번들 톤으로 울리고, 보조 버튼에 `LiveActivityIntent` + `openAppWhenRun = true` → 앱이 뜨면 `AVAudioSession .playback` 으로 개인 목소리 재생.
- 새 발명이 아니다. 안드로이드 `RingingService.startDismissVoiceThenFinish`(719-757)의 "알람 끄면 끝맺음 목소리"를 **기본 경험으로 승격**하는 것이다: *"알람을 끄면, 그 사람이 말을 겁니다."*
- 리스크: 유료 티어의 핵심 약속이 열화한다. 스토어 문구·온보딩에서 **두 티어의 약속이 다름을 숨기지 말 것.**

**1안(승격) — `Library/Sounds` 가 살아 있으면**

- 옛 `AlarmSoundStaging` 그대로. 예약 시점에 클립을 `voice_<alarmId>.caf` 로 변환 저장 → `AlertSound.named(...)`. 우리 클립은 ~200KB ≈ 13초라 30초 상한 안에 들어온다.
- 오프라인 불변식: 클립이 로컬에 없으면 **번들 톤으로 예약해 두고**, 받아지면 재예약.
- 리스크: Apple known issue. 26.x 마이너에서 회귀할 수 있으므로 **1안이 되더라도 2안 경로를 코드에서 지우지 말 것.**

**두 안 공통 리스크(제품 제약으로 굳는다)**

| 잃는 것 | 안드로이드 대응물 |
|---|---|
| 우리 울림 화면(딥네이비 풀스크린) | `RingingActivity.kt` 580줄 — tint color + 버튼 라벨이 전부 |
| 무한 반복 울림 | `VOICE_REPEAT_GAP_MS=900` + `LoudnessEnhancer(+6dB)` — 커스텀 사운드는 1회 재생 |
| 알람음↔목소리 교차 | `AlarmPlayModes.ALARM_VOICE` — 사운드 슬롯이 하나 |
| 알람별 볼륨·페이드인·진동 패턴 | AlarmKit이 노출 안 함. "직접 재생보다 작다" 보고 다수 |
| 30초 초과 문구 | 운세·편지형 대사 → iOS 전용 축약본 필요 |
| 볼륨 버튼 스누즈 | iOS에선 볼륨 버튼이 **해제** |
| iOS 25 이하 | AlarmKit 26.0+ → iPhone의 약 21%를 버린다 |

**카피 규약이 뒤집히는 지점**: CLAUDE.md의 「어떤 경우에도 "울리지 않아요" 라고 쓰지 말 것」은 **iOS에서 무효다.** AlarmKit 권한을 거부하면 대체 경로가 없어 진짜로 안 울린다. iOS 권한 게이트는 "알람이 울리지 않습니다"라고 **정확히** 말해야 한다. 이 규약을 그대로 복사하면 거짓말이 된다.

## 6) 하지 말 것

1. **백그라운드 오디오 상주.** 심사 도박(2.5.4 반려 사례 다수)이고, **사용자가 앱을 스와이프하면 알람이 죽는다.** Alarmy 공식 FAQ도 그렇게 안내한다. `AGENTS.md:29`("알람 발사 정확성은 전부 로컬")와 정면 충돌한다.
2. **Critical Alerts 신청.** 승인 기준은 건강·안전·보안이고 소비자 기상 알람은 그 밴드에 없다. 승인돼도 **30초·1회·전체화면 없음**이라 우리 문제를 못 푼다.
3. **KMP / Flutter / RN.** 위 3.3배 역전.
4. **공유 코어 뽑겠다고 안드로이드를 리팩터링.** `AlarmRepository.kt` 1,721줄에서 `context` 30곳을 걷어내는 작업을 출시 직후에 한다는 뜻이다.

6. **법무문서 v5를 iOS 착수와 함께 올리기.** 전원 재동의가 iOS와 무관한 안드로이드 사용자에게 튄다. 어차피 필요한 다른 개정과 **한 사이클로 묶어라.**
7. **데스크톱 사본으로 복원.** `git revert 9f427c69`(또는 `git show 9f427c69^:apps/ios-native/...`)를 쓴다 — 내용 동일, 이력이 붙어 온다.
8. **prod DB 리셋.** iOS용 `push_tokens` CHECK 복구는 **append-only 마이그레이션 하나**로 한다(#94).
9. **"무음 스위치·방해금지를 뚫습니다"를 폴백 모드에서 쓰기.** AlarmKit일 때만 참이다.

## 7) 시작한다면 첫 2주 — 위험한 가정부터

**Day 0 (반나절) — Go/No-Go. 이게 코드 한 줄보다 먼저다.**
빈 Xcode 프로젝트 + iOS 26 실기기. 옛 코드는 아직 손대지 않는다.
- ① `Library/Sounds` 에 **런타임으로 쓴** `.caf` 가 `AlertSound.named` 로 재생되는가?

## 8) 지금 시작하는 게 맞는가 — 솔직하게

**아니다. Day 0 스파이크만 하고, 본격 착수는 미뤄라.**

세 가지 이유다.

**첫째, 착수 자체가 안드로이드 사용자를 해친다.** iOS의 진짜 관문은 Swift가 아니라 Apple 로그인·결제 복구 → 개인정보처리방침 개정 → `CURRENT_POLICY_VERSION` 4→5 → **전원 재동의**다. prod에 베타 테스터 실데이터가 이미 있고(2026-08-01 확정), 그들은 iOS에서 아무것도 얻지 않으면서 동의 게이트 마찰만 받는다. **막 출시한 제품에 지금 넣을 마찰이 아니다.**

**둘째, 제품의 핵심 약속이 아직 참인지 모른다.** "내 사람 목소리로 깨어난다"가 iOS에서 유료 티어에도 성립하는지가 `Library/Sounds` 한 줄에 걸려 있고, Apple 포럼 기준 **2026-02에도 안 고쳐졌다.** 이게 X면 iOS 판의 유료 약속이 "알람을 끄면 그 사람이 말을 겁니다"로 바뀐다 — **코드 결정이 아니라 제품 결정**이고, 가격·스토어 문구·온보딩이 전부 따라온다. 이걸 모르는 채로 2주를 태우면, 나중에 코드가 아니라 제품 정의를 되돌리게 된다.

**셋째, 1인 개발이 앱 2개를 동시에 든다는 뜻이다.** 지금 안드로이드는 1.2.3을 막 냈고 Codex 리뷰 P1이 계속 나오는 중이다(#675 받은-알람 소유권, #676 탈퇴자 목소리 회수). iOS를 붙이면 **모든 백엔드 변경이 2배로 검증 대상이 된다.** `AlarmKitViewModel.swift` 의 주석이 `RingingService.kt:141-197` 을 짚는 건 자산이지만, 동시에 **한쪽을 고칠 때마다 다른 쪽을 열어봐야 한다는 청구서**이기도 하다.
