## 공유 불가능한 부분

- **Compose UI 20,256줄 (53.5%)** — SwiftUI로 100% 재작성. KMP를 써도 그대로다.
- **AlarmManager** (`alarm/AlarmScheduler.kt`, `AlarmReceiver.kt`, `BootCompletedReceiver.kt`) — iOS에 대응물이 없다. `UNNotificationRequest` + `UNCalendarNotificationTrigger`로 **설계 자체가 바뀐다**(반복 요일 알람 = 요일별 요청 7개, 64개 pending 상한).
- **`ringing/RingingActivity.kt`(580) + `alarm/RingingService.kt`(984)** = 1,564줄. 잠금화면 위 풀스크린 + 포그라운드 서비스 + 볼륨 제어. **iOS에는 이 기능이 없다.** Critical Alerts 엔타이틀먼트(애플 개별 승인)를 받아도 동작이 다르다. 이 앱의 핵심 기능인데 재설계 대상이다.
- **Room 4파일 982줄** (`AlarmDao` 343 / `AlarmDatabase` 237 / `AlarmEntity` 224 / `HolidayEntity` 178).
- **WorkManager 10파일** (`sync/` 793줄) — iOS는 `BGTaskScheduler`(실행 보장 없음).
- **Retrofit/Gson 1,391줄** — JVM 전용. KMP로 가면 Ktor + kotlinx.serialization으로 **전면 재작성**.
- **Play Billing 360줄** → StoreKit 2, **Firebase FCM 114줄** → APNs, **`android.icu.util.ChineseCalendar`**(`IcuLunarConverter.kt` 117줄) → iOS는 `Calendar(identifier: .chinese)`.

## packages/shared 를 iOS 가 쓰는 현실적인 방법

**규모: 3파일 153줄** (`index.ts` 4 / `schemas/auth.ts` 125 / `schemas/voice.ts` 24). export 22개.

내용은 전부가 아니라 **일부**다 — 비밀번호/이메일 인증코드/비번재설정 스키마, `DISPLAY_NAME_MAX_LENGTH`(30) · `VOICE_NAME_MAX_LENGTH`(50), `normalizeDisplayName`/`clampDisplayName`/`DisplayNameSchema`, 로그인/가입 요청 스키마, 목소리 프리뷰 텍스트.

중요한 사실 셋:

1. **백엔드조차 거의 안 쓴다.** 24개 라우트 파일 10,490줄 중 `@alarmtalk/shared`를 import하는 건 **3개**(`auth.ts`, `user.ts`, `voice-profile.ts`)뿐. 알람·빌링·가족·TTS 계약은 shared에 없다.
2. **codegen도 OpenAPI도 없다.** 레포 전체에 스펙 파일이 없고, 안드로이드는 Retrofit 인터페이스 + Gson `@SerializedName`으로 **수기 중복**하고 있다.
3. **안드로이드가 이미 손으로 번역해 놨다.** `CodeRedeemField.kt:76-77`의 `DisplayNameMaxLength = 30` / `VoiceNameMaxLength = 50`은 shared의 TS 상수를 그대로 옮긴 것이다. CLAUDE.md가 "shared가 유일 출처"라 못박아도 실제로는 **손으로 동기화 중**이다.

**현실적 방법 (권장순):**

- **수기 번역 (권장).** 153줄이다. Swift로 옮기면 반나절~1일. 안드로이드가 이미 그렇게 하고 있으므로 방식이 늘지 않는다. 정규식(`INVISIBLE_RE`)·서러게이트 절단 로직은 Swift에서 오히려 더 안전하게 쓸 수 있다(`String`이 grapheme 단위).
- **zod → JSON Schema → Swift 코드생성.** `zod-to-json-schema` + `quicktype`. 153줄 얻자고 파이프라인·CI 스텝을 새로 만드는 건 비용이 산출보다 크다. 게다가 `normalizeDisplayName`/`clampDisplayName`은 **함수라 스키마 생성으로 안 나온다** — 결국 손으로 옮겨야 한다.
- **KMP 공통 모듈로 승격.** shared를 Kotlin으로 다시 쓰고 백엔드는 TS를 유지 → **출처가 셋(TS/Kotlin/Swift)** 이 되어 지금보다 나빠진다.

**정작 필요한 계약은 shared에 없다.** iOS가 실제로 재현해야 하는 건 10,490줄짜리 백엔드 라우트의 요청/응답 형태이고, 그건 지금 **안드로이드 Retrofit 인터페이스 1,391줄이 유일한 기술서**다. 언어 선택과 무관하게 이 1,391줄은 어떤 형태로든 옮겨야 한다.

## KMP 도입 시 실제로 절약되는 양 vs 드는 비용 (숫자로)

**절약: 약 1,300~1,500줄 (안드로이드 코드의 3.5~4%)**

- 즉시 이동: 681줄
- 리팩터링 후 이동: ~630줄
- 안전망: 순수 JVM 테스트 18파일 1,604줄 중 이 코어를 직접 덮는 건 **536줄** — `AlarmTimeCalculatorTest`(152) · `RemoteAlarmMapperTest`(107) · `InputSanitizerTest`(90) · `DeliveryTagStripTest`(78) · `GreetingStockClipTest`(67) · `VoiceVolumeRampTest`(42). 여기에 weatherVariant 계열 362줄(`AlarmRepositoryWeatherVariantTest` 190 + `WeatherVariantRefreshTest` 172)이 B그룹을 덮는다. **핵심 계산은 테스트가 있다 — 추출 자체는 안전하다.**

**비용: 최소 4,000줄 이상을 건드리고, 안드로이드 앱의 기존 동작을 위험에 노출**

| 항목 | 줄 | 내용 |
|---|---|---|
| Retrofit/Gson → Ktor/kotlinx.serialization | 1,583 | API 8파일 1,391 + `AlarmTalkApiClient` 144 + `ApiErrors` 48. **작동 중인 안드로이드 네트워크 전면 교체** |
| Room → Room KMP 또는 SQLDelight | 982 | 4파일. 마이그레이션 히스토리 있는 실사용 DB |
| `AlarmRepository` 분해 | 1,721 | Context 30곳 제거하고 순수/플랫폼 분리 |
| 빌드·CI | — | KMP Gradle, XCFramework, Xcode 통합, 필수체크 7개 재구성 |
| **합계** | **4,286줄+** | |

**비율: 1,300줄 얻으려고 4,286줄을 건드린다. 3.3배 역전.**

게다가 KMP를 넣어도 iOS 쪽에서 **여전히 새로 써야 하는 것**: SwiftUI 화면 전량(안드 20,256줄에 대응), `UNUserNotificationCenter` 스케줄링, Critical Alerts, StoreKit 2, APNs, `Localizable.strings` 896×3, 잠금화면 울림 화면 재설계.

**세 후보의 숫자 요약:**

| | 재사용되는 안드 코드 | 안드로이드 회귀 위험 | 새 툴체인 |
|---|---|---|---|
| **(a) Swift/SwiftUI** | 0줄 (단, 1,300줄은 **읽고 옮기면 됨** — 로직 자체는 참고 가능) | 없음 | 없음 |
| **(b) KMP** | 1,300~1,500줄 (3.5~4%) | **높음** — 네트워크·DB 전면 교체 | Gradle KMP + XCFramework |
| **(c) Flutter/RN** | 0줄 | 안드로이드 앱 자체를 버리거나 앱 2개 유지 | 전체 |

(c)는 이 앱에선 특히 나쁘다 — `alarm/`+`ringing/`+`sync/` 2,938줄이 전부 플랫폼 채널 네이티브 코드로 다시 나와야 하고, 결국 Dart/JS 레이어가 **추가**될 뿐 네이티브 코드가 사라지지 않는다.

**핵심 판단 근거:** 공유할 코어가 "적다"가 아니라 **없다시피 하다**(1.8%가 즉시 이식 가능, 4%가 상한). 그리고 이 앱의 정체성인 정시 울림·잠금화면 점유·포그라운드 재생(1,564줄)은 iOS에서 **로직 공유 문제가 아니라 설계 재검토 문제**다. KMP가 그 부분에서 해 주는 일은 0이다.
