# v1.3 시연 소재 · 캠페인 링크 · 관찰 기록

v1.3 지시서 16.2·16.3(W17)의 작업 원본이다. 시연 소재 세 가지의 대본과 촬영 목록, 캠페인 링크 규칙, 설치 뒤 연결이 지금
되는지에 대한 사실, 처음 쓰는 사람 관찰 안내서와 기록표 틀을 한곳에 둔다. 공개 문구(랜딩·`llms.txt`·스토어 설명)의
원문은 여기가 아니라 [`apps/landing/messages/`](../../apps/landing/messages/ko.json)·[`llms.txt`](../../apps/landing/public/llms.txt)·
[`app-store-listing.md`](app-store-listing.md)·[`play-store-listing.md`](play-store-listing.md) 에 있다.

## 1. 지키는 것

- **실제 빌드의 화면만** 찍는다. 화면을 합성하거나 아직 운영에 없는 기능(광고 보상, 날짜 1회 '내일 한 줄' 등)을 보여 주지
  않는다. 찍는 날 그 기능이 운영에 있는지 먼저 본다 — 무료 직접 입력 3회는 서버(#942)와 잠금을 푼 v1.3 빌드가 함께 있어야
  보이고, 무료 체험은 스토어 오퍼(`docs/spec/plan-gates.md` 「신규 1개월 무료」)가 살아 있어야 한다.
- **권리가 확인된 목소리·얼굴만** 쓴다. 등록 목소리는 출연자 본인 것이거나, 목소리 주인이 광고 사용까지 서면으로 허락한
  것이다. 유명인·성우·캐릭터·다른 영상에서 따온 목소리는 쓰지 않는다(지시서 16.1 — 앱 규칙도 본인 또는 허락받은 목소리).
  기본 목소리 4종(시우·미나·도현·애니)의 클립을 광고에 쓰는 조건은 오너가 음성 공급사 약관으로 확인한다(확인 전에는 쓰지 않는다).
- **쓰지 않는 말**: 광고 보상(운영 전 — `docs/spec/ad-rewards.md` §6), 커플·가족 이용권·목소리 공유·남에게 보내는 알람,
  선물·프로모·초대 코드(없다 — `docs/spec/plan-gates.md`). '가입하면 1개월 무료' 도 쓰지 않는다 — 체험은 **처음 구독할 때**
  스토어가 주고, **끝나면 자동으로 결제**된다. 체험을 말하는 소재는 같은 화면에 자동 결제와 해지 방법을 함께 적는다.
- 자막·설명에 줄표(`—`)를 쓰지 않는다(스토어 문구와 같은 규칙).
- 숫자는 지금 값이다: 직접 입력 무료 월 3회(기본 목소리)·플러스 월 30회, 플러스 월 3,900원 / $3.90 / 390円. 바뀌면 여기부터 고친다.

## 2. 시연 소재 3종

캠페인 ID 는 소재 하나에 하나다. 같은 소재의 길이·자막 변형은 `utm_content` 로 가른다(「3. 링크 규칙」).

### A. 실제 기상 소리 — `v13_wake_real`

| 칸 | 내용 |
| --- | --- |
| 앱에서 연결할 행동 | **첫 알람 만들기**(무료, 기본 목소리) |
| 랜딩 URL | `https://alarm-talk.com/?utm_source=<채널>&utm_medium=<매체>&utm_campaign=v13_wake_real&utm_content=<변형>` |
| 들려줄 음성 | 기본 목소리 **미나**의 날씨 문구. 촬영한 날 그 지역 예보로 앱이 고른 클립을 **녹화된 그대로** 쓴다(편집으로 다른 클립을 끼우지 않는다) |
| 권리 확인 | 기본 목소리 클립의 광고 사용 조건(오너) · 화면에 개인 정보(이메일·알림)가 비치지 않는지 |

촬영 목록(실제 기기, 실제 시각):
1. 밤. 알람 탭의 ＋ → 타임휠로 내일 오전 6:30 → 목소리 '미나' → 문구 '날씨' → 지역 '서울'(목록에서 고른다, 위치 권한 없음) → 저장.
2. 홈에 "N시간 M분 후에 울려요." 가 뜬 화면(앱이 실제로 쓰는 문장).
3. 아침. 잠긴 폰에서 전체 화면으로 울리는 장면과 실제 소리(소리를 덧입히지 않는다). 끄기까지.

자막(ko / en / ja):
1. "시간을 고르고" / "Pick a time" / "時間を選んで"
2. "목소리를 고르면 준비 끝" / "Pick a voice, and you're set" / "声を選べば準備完了"
3. "아침엔 그 목소리가 날씨를 읽어 줘요" / "In the morning, that voice reads you the weather" / "朝はその声が天気を読み上げます"

| --- | --- |

## 3. 링크 규칙

| 파라미터 | 값 | 예 |
| --- | --- | --- |
| `utm_source` | 채널(소문자 · 영문 · 숫자 · `_`) | `instagram`, `youtube`, `naver_blog`, `kakao` |
| `utm_medium` | 매체 종류 | `organic`, `paid_social`, `creator`, `community` |
| `utm_campaign` | 위 캠페인 ID 그대로 | `v13_wake_real` |
| `utm_content` | 소재 변형(길이 · 자막 · 언어) | `wake_real_15s_ko_a` |

- 위 네 개만 쓴다. 다른 파라미터를 붙이지 않는다.
- **이메일·전화번호·이름·계정 id·문구 원문을 URL 에 넣지 않는다.** 링크는 남에게 전달되고 로그·리퍼러에 남는다.
  `utm_content` 에도 사람을 가리키는 값(크리에이터 본명 등)이 아니라 소재 id 를 쓴다.
- **쿠폰·초대·프로모 코드를 링크에 싣거나 링크로 유료 기능을 여는 흐름은 없다**(`docs/spec/plan-gates.md` · AGENTS.md P1).
  할인·무료는 스토어 장치(첫 구독 무료 체험, App Store 오퍼 코드, Play 프로모션 코드)로만 주고, 그것도 스토어 화면에서 쓴다.
- 언어별 랜딩은 경로로 가른다(`/`, `/en/`, `/ja/`). 언어를 파라미터로 싣지 않는다.

## 4. 설치 뒤 연결 — 지금 되는 것과 안 되는 것 (코드로 확인, 2026-10-26)

| 구간 | 지금 | 근거 |
| --- | --- | --- |
| 광고 → 랜딩 | `utm_*` 가 붙은 채 열린다 | — |
| 랜딩에서 utm 을 읽어 남기기 | **안 된다** — 랜딩에 분석 스크립트가 없다 | `apps/landing`(분석 의존성 없음) |
| 랜딩 → 스토어 | **utm 이 끊긴다** — 스토어 배지가 고정 주소다 | `apps/landing/lib/site.ts` 의 `STORE_LINKS` |
| 스토어 → 설치 | 스토어 콘솔이 자기 링크의 파라미터만 센다(아래) | — |
| 설치 → 앱 첫 실행에서 캠페인 읽기 | **안 된다** — Android 는 Play 설치 리퍼러를 읽지 않고, iOS 는 그런 장치가 없다 | `AndroidManifest.xml`(Install Referrer 없음) |
| 링크로 앱의 특정 화면 열기(딥링크) | **안 된다** — Android `MainActivity` 는 `MAIN/LAUNCHER` 뿐(VIEW·App Links 없음), iOS 는 URL 스킴·연결 도메인이 없다 | `apps/android-native/app/src/main/AndroidManifest.xml`, `apps/ios-native/project.yml` |
| 첫 예약 · 다음 주 사용 · 결제 | 전체 합계만 있다(관리자 콘솔 개요 · 사용 기록) — **채널별로 나눌 수 없다** | `docs/spec/admin-console.md`, `docs/spec/usage-events.md` |

그래서 지금 캠페인은 **"앱 열기 → 첫 알람"** 까지 사용자가 스스로 간다. 소재의 끝 화면은 앱 안 경로를 말로 안내한다
(A: 알람 탭 ＋ / B: 목소리 탭 → 추가 / C: 알람 편집 → 문구 → 직접 입력).

측정은 이렇게 표시한다:
- **스토어 직접 링크**(소재마다 따로 만든다 — 랜딩을 거치지 않는 링크): Play 는 스토어 주소의 `referrer` 에 utm 을 싣고
  (`https://play.google.com/store/apps/details?id=com.alarmtalk.app&referrer=utm_source%3D…%26utm_medium%3D…%26utm_campaign%3D…`),
  App Store 는 App Store Connect 가 주는 캠페인 링크(`pt`=제공자 토큰, `ct`=캠페인 토큰)를 쓴다. 두 콘솔이 어떤 지표를 어디까지
  보여 주는지는 **콘솔에서 직접 확인한다**(이 문서를 쓸 때 확인하지 않았다). App Store 분석은 데이터 공유에 동의한 사용자만 센다.
- 랜딩을 거친 유입·설치 뒤 행동은 **미연결**로 적는다. 날짜가 맞는다고 채널 효과로 읽지 않는다.
- **클릭 수만으로 성공을 말하지 않는다.** 보고는 채널별 노출·클릭·스토어 방문·설치(콘솔) 와 전체 합계의 첫 알람·다음 주
  사용·결제를 **나란히** 두고, 둘을 잇는 칸은 '미연결' 로 둔다.
- v1.3 은 여러 기능을 함께 냈다(무료 직접 입력·무료 체험·녹음 판정 등). **출시 전후 비교로 한 기능의 효과를 주장하지 않는다.**

연결을 만들려면(지금 하지 않았다 — 오너 결정): 랜딩 배지가 들어온 utm 을 Play `referrer` 로 넘기기, Android 에 Play 설치
리퍼러 읽기 + 개인정보 처리방침 반영, 두 앱 딥링크(App Links · 연결 도메인)와 그 경로의 로그인·동의 게이트 처리.

## 5. 처음 쓰는 사람 관찰 (5~8명)

**목적**: 설치부터 첫 알람이 울릴 때까지 어디서 멈추는지 본다. 기능 선호 조사가 아니다.

**모집**: 알람톡을 써 본 적 없는 사람 5~8명. 기기는 Android·iPhone 을 섞는다(각 2명 이상). 가족·연인 목소리를 등록할 사람이
있으면 그 사람의 동의를 미리 받는다(B 흐름). 사례·보상은 스토어 결제와 무관한 것으로(앱 이용권을 주지 않는다 — 코드로 여는 길이 없다).

**진행(40분)**:

## 6. '내일 한 줄' 탐색 기록 (10~20명 · 2주)

'내일 한 줄'(날짜 1회 알람, 지시서 W10)이 **운영에 나간 뒤** 시작한다 — 2026-10-26 develop 에는 없다. 그 전에는 직접 입력으로
같은 질문의 앞부분(하루 한 문장을 쓰려고 하는가)만 볼 수 있다.

**질문**: 사람들이 다음 날 아침에 들을 한 문장을 스스로 쓰는가, 2주 동안 얼마나 이어지는가, 어디서 그만두는가.
**하지 않는 것**: 효과 주장(인과), 감정 분석, 문장 원문 수집. 문장 내용은 참여자가 보여 주고 싶을 때만, 그 자리에서 메모한다.
