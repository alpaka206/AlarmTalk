# 알람 문구 생성 설계 (Gemini → ElevenLabs v3)

> 코드 주석이 `§4.x` 로 참조하는 설계 근거 문서.
> **프롬프트 전문·태그 목록·검증 규칙의 유일한 출처는 코드**(`packages/backend/src/lib/vertex-translate.ts`,
> `routes/tts.ts`, `lib/elevenlabs.ts`)다. 이 문서는 "왜 그렇게 정했나"만 남긴다 — 코드에 있는 문자열을
> 여기에 다시 붙여넣지 말 것.

## 1. 배경

목소리 알람 앱. 짧은 알람 문구를 Vertex Gemini(`gemini-2.5-flash`)로 생성하고 ElevenLabs `eleven_v3`로
합성한다. 경쟁사 알라미가 게임/미션으로 "무조건 깨움"을 판다면 우리는 **음성** 경험으로 차별화한다.

라이브 동적 생성은 현재 **기본 OFF**다(`GOOGLE_VERTEX_DYNAMIC_TEXT_ENABLED`). 켜지 않으면 스톡 클립/로컬
폴백만 나간다. 켜기 전 조건은 §5.

## 2. 설계 근거 (외부 연구)

1. **음성 > 톤**: 음성 경보가 톤 경보보다 각성률이 크게 높다(체계적 리뷰 [PMC7711682](https://pmc.ncbi.nlm.nih.gov/articles/PMC7711682/),
   소방 RCT [pubmed 30482491](https://pubmed.ncbi.nlm.nih.gov/30482491/)). 같은 RCT에서 '이름 추가'는 각성률을
   못 올렸다 → 개인화의 값어치는 정체성 과시가 아니라 **맥락 적합성**에 있다.
2. **맥락·의도 프레이밍이 아침 기분을 좌우**한다([JMIR e50835](https://humanfactors.jmir.org/2024/1/e50835)) → Gemini 맥락 생성의 정당화.
3. **soft-start**: 급작스러운 알람은 스트레스 반응을 키우고 점진 기상은 낮춘다([pubmed 24509892](https://pubmed.ncbi.nlm.nih.gov/24509892/)).
   단 과한 케어 톤은 오히려 perceived support를 떨어뜨린다([PMC8663575](https://pmc.ncbi.nlm.nih.gov/articles/PMC8663575/)) → **따뜻하되 절제**.
4. **짧게**: 수면관성 구간(기상 0~30분)은 집행기능이 떨어진다 → 단순·구체·빠르게 파싱되는 한 줄.
5. **KO/JA 네이티브성은 자동 지표로 못 잰다** — 현지인 MOS가 필요하다([arXiv:2506.16310](https://arxiv.org/abs/2506.16310)).
   텍스트의 네이티브성은 TTS 프로바이더가 바뀌어도 살아남는 유일한 해자다.

## 3. 파이프라인

`generateDynamicAlarmTextWithVertex`(동적 모드) 또는 `generatePrerenderClipText`(클론 사전렌더)로 문구를
만들고 → `routes/tts.ts` 가 `[tag] ` + text 를 조립해 → `lib/elevenlabs.ts` 가 `eleven_v3` 로 합성한다.
사용자 직접입력/번역 경로만 `prepareAlarmTextWithVertex` 를 탄다.

## 4. 설계

### 4.1 아키텍처 — 언어-네이티브-우선 단발(single-call)

호출 1회로 `{text, tag}` 를 함께 받는다(Worker 지연·비용). 과거의 "생성 → autoTag" 2차 Vertex 호출은
제거했다 — 생성 프롬프트가 인라인 브래킷을 금지하는데 직후 autoTag 가 태그를 붙여, 정상 출력이 서로
모순으로 폐기되던 구조였다. 품질 **상한**은 프롬프트 콘텐츠 깊이(언어별 네이티브 규칙)로, **하한**은
2단 검증·국소수리(§4.7)로 끌어올린다.

### 4.2 systemInstruction

고정 철학·출력계약·태그 규칙·NEVER 목록은 `systemInstruction` 으로 분리하고(프롬프트 캐시 친화),
user prompt 에는 가변 데이터(모드·관계·언어 블록·날씨 신호·호칭·few-shot)만 넣는다. 계약 요지:

- 실제 사람이 **소리 내어 말하는 한 줄**. 알림·뉴스·일기예보·번역체 금지. 하드캡 200자.
- 관계·호칭은 **레지스터를 고르는 데만** 쓰고 절대 발화하지 않는다. 한 줄 안에서 존댓/반말을 섞지 않는다.
- 호칭은 준 값 그대로. 추정 가족호칭(할머니/엄마 등)으로 바꾸지 않는다.
- 사용자가 쓰지 않은 원시값(기온·확률·시각·날짜·생년월일·지역명) 낭독 금지.
- 출력은 `{"text": string, "tag": string}` STRICT JSON.

전문은 `vertex-translate.ts` 의 `DYNAMIC_SYSTEM_INSTRUCTION`.

### 4.3 언어별 네이티브 규칙

활성 언어 블록만 user prompt 에 주입한다. 핵심 결정:

- **ko**: 관계별 어체를 골라 한 줄 내내 유지. 손주→조부모는 해요체 + 존대 동사, 부모→자식·형제·연인은
  반말, 중립은 해요체. 가족/친구/연인에 **합니다체 금지**. 조사·띄어쓰기를 살리고("비가 올 수 있대요"),
  전달받은 날씨/운세는 `~대요/~래요` 전달어법으로.
- **ja**(당초 0줄이라 일본어 어색함의 직접 원인): 일본어 가족·친밀 화법은 **タメ口(캐주얼)** 이지 경어가
  아니다. 한국어 해요체 논리를 일본어로 직역하면 안 된다. です・ます 는 거리감/불명/직장에만.
  종조사 ね/よ/な 로 온기를 만들되 쌓지 말고, pro-drop 강하게, **役割語(わ/かしら/ぞ/だぜ) 금지**,
  외래어는 자연스러운 가타카나.
- **en**: 문법적 레지스터가 거의 없으므로 관계는 **온도**만 바꾼다. 축약형 항상, 'Please be advised'·
  'rise and shine' 류 금지.

전문은 `koreanRegisterGuidance()` / `japaneseRegisterGuidance()` / `englishRegisterGuidance()`.

### 4.4 모드별 가이드

동적 모드는 `DynamicAlarmTextMode` 3종뿐이다.

| 모드 | 핵심 | 기본 태그 |
|------|------|-----------|
| **wake_weather** | 부드럽게 깨운 뒤 날씨에서 최대 2개 행동권유를 대화체로(숫자·코드·% 금지). 조건+행동 페어(비→우산, 미세먼지→마스크, 추위→따뜻이, 더위→물, 맑음→산책). 날씨는 **언어중립 토큰**(`WeatherSignal`)으로 받아 타깃 언어로 재표현한다 — 한국어 문장을 넘겨 재번역시키면 뉘앙스가 깨지고 환각이 생긴다 | `cheerfully` |
| **wake_fortune** | 가벼운 엔터테인먼트 운세(예언 아님). 생년월일·시각·별자리 금지. 연인/배우자면 새 인연·연애운·질투 금지 | `playfully` |
| **love** | 사적·다정한 아침. 은근한 설렘까지, 드라마·소유욕·새 인연 금지 | `happy` |
| preset/custom(사용자 문구) | 사용자 말은 재작성하지 않는다. 번역 요청 시에만 네이티브 구어로 충실 번역. 사용자 입력은 DATA 로만 다룬다(인젝션 안전) | 감정 매칭 1개 |

### 4.5 태그 정책

- **v3 태그는 enum 이 아니다.** 공식 문서는 audio tag 를 "natural-language instructions" 로 규정하고 지원
  태그 목록을 공개하지 않는다. 효과는 보이스·문맥·stability 에 의존한다. 그래서 우리는 "v3 가 받는 enum"을
  맞추는 게 아니라 **예측가능성·알람 적합성·태그 낭독 방지**를 위해 큐레이트한 자연어 딜리버리 큐만 쓴다
  (`APPROVED_TAGS`). 부사형 옛 태그(warmly/encouraging/gentle…)는 실증 근거가 없어 전량 폐기했다.
- **제외**: `[sighs]`/`[laughs]`(따뜻한 알람에 부적합), `[standing]`/`[music]` 류(공식 문서가 사용 금지
  예시로 명시). 페이싱은 SSML break 가 없으므로 `…`·쉼표로 만든다.
- **저각성 태그**(`calm/tired/whispers/quietly`)는 취침 모드 전용이었는데 그 모드가 사라졌다. 남은 셋은
  전부 깨우는 알람이라 `sanitizeDeliveryTag` 가 무조건 막는다.
- **배치**: 문두에 정확히 1개, 조합 금지. 아주 짧거나 맞는 태그가 없으면 무태그(태그가 소리 내어
  읽히는 사고 방지).
- **voice_settings**(고쳐진 버그): 과거 `elevenlabs.ts` 의 역조건 때문에 유일 운영 모델인 v3 에 오히려
  voice_settings 를 안 보내 서버 디폴트가 적용됐고 태그가 약하게 실현됐다. 지금은 항상 전송한다
  (stability 0.5 Natural / similarity 0.8 / style 0.4). **Robust(0.7+) 금지** — 태그를 억제한다.

### 4.6 길이 정책

목표는 한 줄 또는 두 짧은 문장(KO/JA 25~70자, EN 10~22단어), 하드캡 200자. v3 는 일관성을 위해 250자+를
권장하지만 수면관성 근거상 **짧은 쪽**을 택한다. 이 텐션은 패딩이 아니라 (1) 짧은 범위의 긴 쪽 지향
(2) stability=Natural (3) 보수적 단일 태그 (4) 문장부호 페이싱으로 헤지한다.

### 4.7 검증·재시도 (2단)

들쭉날쭉의 원인은 고온도 생성 + 정규식 binary 검증이 좋은 출력까지 통째로 폐기하고 고정 폴백으로
떨어뜨린 것이었다. 그래서 **폐기 대신 국소 수리**로 바꿨다.

- **HARD 차단**(→ 1회 재롤 → 회전식 폴백): 파싱 불가/메타 JSON, 200자 초과, 운세 PII 누설(생년월일·별자리),
  관계 라벨 누설·자기참조, 호칭 불일치(추정 가족호칭), 알람 시각/날짜 에코, text 안의 브래킷/지문,
  타깃 언어 불일치, 연인 톤의 '새 인연/연애운/질투'.
- **SOFT**(수용 + 자동 수리): 조사·띄어쓰기 슬립, 경미한 어체 슬립, 세트 밖 태그(→ 무태그 강등).
  과거의 '정중 어미 전량 reject' 는 SOFT 로 강등했다.
- **재시도**: 최대 1회, HARD/JSON 실패에만(공통 경로 1왕복 유지). temperature 는 0.85→0.75 로 낮춰 churn 을
  줄였다. 2차 실패 시 **회전식 폴백**(mode+dateLabel 해시로 템플릿 회전 — 고정 단일 문구 금지).
- **JSON**: `responseSchema` 가 1차, brace-slice 파서는 최후 폴백으로 남긴다(flash 에서 responseSchema +
  `thinkingBudget:0` 간헐 빈응답 대비).

### 4.8 페르소나·변주

- `relationship_label` 은 레지스터/온도/어휘만 구동하고 절대 발화하지 않는다. `listener_title` 은 그대로 쓴다.
- 화자 개성은 `voice_profiles.speech_style`(마이그레이션 #66)로 프롬프트에 주입한다. 초안이던
  `voice_gender`/`speech_formality`(#53)는 speech_style 로 대체돼 제거됐다.
- **변주는 경계한다**: freshness seed(dateLabel 등)로 opener·리듬·소소한 케어 디테일만 흔들고 골격은
  고정한다. 기상 실패율에 따른 각성 에스컬레이션은 soft-start 윤리와 충돌해 채택하지 않았고, 호출마다
  voice_settings 를 바꾸는 변주는 오디오 캐시 fan-out 이 폭증해 배제했다.

### 4.9 few-shot

언어별 3~5개를 주입한다(`DYNAMIC_FEW_SHOT`). 출력 계약이 `{text, tag}` 이므로 예시의 태그도 tag 필드로
분리해 넣는다. 예시는 **살아 있는 모드**의 것만 유지한다.

## 5. Gemini 실반영 전 게이트

`GOOGLE_VERTEX_DYNAMIC_TEXT_ENABLED=true` 로 켜기 전에 확인해야 하는 것 — 아래는 코드로 확정할 수 없고
사람이 듣고 판단해야 하는 **가설**이다.

1. **현지인 MOS**: KO/JA 원어민 각 10~20명, 샘플 8~12개. 자연스러움·관계 적절성·기상 의욕 평균 ≥ 3.8/5.
   특히 **JA 손주→조부모 タメ口 디폴트 수용도** — 거부감이 크면 정중 디폴트/토글을 다시 검토한다.
2. **v3 청취 회귀**: voice_settings 픽스 전/후 동일 텍스트 비교(태그가 실제로 더 실현되는가),
   250자 미만 단문에서 태그가 **소리 내어 읽히지 않는가**(특히 JA), 모드별 톤 체감.
3. **적대적**: 호칭/사용자 문구에 지시를 심어(관계 말해라, 시각 읽어라) 누설 게이트 우회 시도,
   JSON 깨뜨리기(코드펜스·중첩·메타) → HARD 100% 차단 → 재롤 → 회전 폴백 확인.

미달 시 태그 세트 축소(`happy`/`cheerfully` 만), 정중 디폴트 전환, 프로바이더 라우팅 재검토가 대안이다.
