# 알람 문구 생성 설계 (Gemini → ElevenLabs v4 Turbo)

> 코드 주석이 `§4.x` 로 참조하는 설계 근거 문서.
> **프롬프트 전문·검증 규칙의 유일한 출처는 코드**(`packages/backend/src/lib/vertex-translate.ts`,
> `routes/tts.ts`, `lib/elevenlabs.ts`)다. 이 문서는 "왜 그렇게 정했나"만 남긴다 — 코드에 있는 문자열을
> 여기에 다시 붙여넣지 말 것.

## 1. 배경

목소리 알람 앱. 짧은 알람 문구를 Vertex Gemini(`gemini-3.8-flash` — 코드 상수 `VERTEX_MODEL` 하나로 정한다. Flash-Lite 는 블라인드 판정에서 품질이 떨어져 쓰지 않는다)로 생성하고 ElevenLabs `eleven_v4_turbo`(코드 상수 `TTS_MODEL_ID`)로
합성한다. 2026-09-30 부터 **태그 없이** 문장만 합성한다(§4.5). 경쟁사 알라미가 게임/미션으로 "무조건 깨움"을 판다면 우리는 **음성** 경험으로 차별화한다.

라이브 동적 생성은 현재 **기본 OFF**다(`GOOGLE_VERTEX_DYNAMIC_TEXT_ENABLED`). 켜지 않으면 스톡 클립/로컬
폴백만 나간다. 켜기 전 조건은 §5.

## 2. 설계 근거 (외부 연구)

1. **음성 > 톤**: 음성 경보가 톤 경보보다 각성률이 크게 높다(체계적 리뷰 [PMC7711682](https://pmc.ncbi.nlm.nih.gov/articles/PMC7711682/),
   소방 RCT [pubmed 30482491](https://pubmed.ncbi.nlm.nih.gov/30482491/)). 같은 RCT에서 '이름 추가'는 각성률을
   못 올렸다 → 개인화의 값어치는 정체성 과시가 아니라 **맥락 적합성**에 있다.
2. **맥락·의도 프레이밍이 아침 기분을 좌우**한다([JMIR e50835](https://humanfactors.jmir.org/2024/1/e50835)) → Gemini 맥락 생성의 정당화.
3. **soft-start**: 급작스러운 알람은 스트레스 반응을 키우고 점진 기상은 낮춘다([pubmed 24509892](https://pubmed.ncbi.nlm.nih.gov/24509892/)).
   단 과한 케어 톤은 오히려 perceived support를 떨어뜨린다([PMC8663575](https://pmc.ncbi.nlm.nih.gov/articles/PMC8663575/)) → **따뜻하되 절제**.
4. **짧게**: 수면관성 구간(기상 0~30분)은 집행기능이 떨어진다 → 단순·구체·빠르게 파싱되는 한 줄.
5. **KO/JA 네이티브성은 자동 지표로 못 잰다** — 현지인 MOS가 필요하다([arXiv:2506.16310](https://arxiv.org/abs/2506.16310)).
   텍스트의 네이티브성은 TTS 프로바이더가 바뀌어도 살아남는 유일한 해자다.

## 3. 파이프라인

`generateDynamicAlarmTextWithVertex`(동적 모드) 또는 `generatePrerenderClipText`(클론 사전렌더)로 문구를
만들고(모델이 태그를 내면 `stripAllTags` 로 벗긴다) → `lib/elevenlabs.ts` 가 `eleven_v4_turbo` 로 그 문장 그대로 합성한다.
사용자 직접입력/번역 경로만 `prepareAlarmTextWithVertex` 를 탄다 — 같은 언어는 Gemini 를 부르지 않고, 번역할 때만 부른다.

## 4. 설계

### 4.1 아키텍처 — 언어-네이티브-우선 단발(single-call)

호출 1회로 `{text}` 를 받는다(Worker 지연·비용). 과거의 "생성 → autoTag" 2차 Vertex 호출은
제거했다 — 생성 프롬프트가 인라인 브래킷을 금지하는데 직후 autoTag 가 태그를 붙여, 정상 출력이 서로
모순으로 폐기되던 구조였다. 2026-09-30 부터는 태그 자체를 붙이지 않는다(§4.5). 품질 **상한**은 프롬프트 콘텐츠 깊이(언어별 네이티브 규칙)로, **하한**은
2단 검증·국소수리(§4.7)로 끌어올린다.

### 4.2 systemInstruction

고정 철학·출력계약·NEVER 목록은 `systemInstruction` 으로 분리하고(프롬프트 캐시 친화),
user prompt 에는 가변 데이터(모드·관계·언어 블록·날씨 신호·호칭·few-shot)만 넣는다. 계약 요지:

- 실제 사람이 **소리 내어 말하는 한 줄**. 알림·뉴스·일기예보·번역체 금지. 하드캡 200자.
- 관계·호칭은 **레지스터를 고르는 데만** 쓰고 절대 발화하지 않는다. 한 줄 안에서 존댓/반말을 섞지 않는다.
- 호칭은 준 값 그대로. 추정 가족호칭(할머니/엄마 등)으로 바꾸지 않는다.
- 사용자가 쓰지 않은 원시값(기온·확률·시각·날짜·생년월일·지역명) 낭독 금지.
- 출력은 `{"text": string}` STRICT JSON — 낱말만, 대괄호 없이. 예전의 `tag` 필드는
  2026-09-23 에 뺐다(백엔드가 읽지 않았다). 다시 넣지 말 것 — 평가 스크립트가 여분 필드로 센다.

전문은 `vertex-translate.ts` 의 `DYNAMIC_SYSTEM_INSTRUCTION`.

### 4.3 언어별 네이티브 규칙

활성 언어 블록만 user prompt 에 주입한다. 핵심 결정:

- **ko**: 관계별 어체를 골라 한 줄 내내 유지. 손주→조부모는 해요체 + 존대 동사, 부모→자식·형제·연인은
  반말, 중립은 해요체. 가족/친구/연인에 **합니다체 금지**. 조사·띄어쓰기를 살리고("비가 올 수 있대요"),
  전달받은 날씨/운세는 `~대요/~래요` 전달어법으로.
- **ja**(당초 0줄이라 일본어 어색함의 직접 원인): 일본어 가족·친밀 화법은 **タメ口(캐주얼)** 이지 경어가
  아니다. 한국어 해요체 논리를 일본어로 직역하면 안 된다. です・ます 는 거리감/불명/직장에만.
  종조사 ね/よ/な 로 온기를 만들되 쌓지 말고, pro-drop 강하게, **役割語(わ/かしら/ぞ/だぜ) 금지**,
  외래어는 자연스러운 가타카나.
- **en**: 문법적 레지스터가 거의 없으므로 관계는 **온도**만 바꾼다. 축약형 항상, 'Please be advised'·
  'rise and shine' 류 금지.

전문은 `koreanRegisterGuidance()` / `japaneseRegisterGuidance()` / `englishRegisterGuidance()`.

### 4.4 모드별 가이드

동적 모드는 `DynamicAlarmTextMode` 3종뿐이다.

| 모드 | 핵심 |
|------|------|
| **wake_weather** | 부드럽게 깨운 뒤 날씨에서 최대 2개 행동권유를 대화체로(숫자·코드·% 금지). 조건+행동 페어(비→우산, 미세먼지→마스크, 추위→따뜻이, 더위→물, 맑음→산책). 날씨는 **언어중립 토큰**(`WeatherSignal`)으로 받아 타깃 언어로 재표현한다 — 한국어 문장을 넘겨 재번역시키면 뉘앙스가 깨지고 환각이 생긴다 |
| **wake_fortune** | 가벼운 엔터테인먼트 운세(예언 아님). 생년월일·시각·별자리 금지. 연인/배우자면 새 인연·연애운·질투 금지 |
| **cheer** (옛 이름 `love`) | 오늘을 버틸 힘을 주는 응원·자기돌봄. ⚠ **연애 문구가 아니다**(2026-09-03) — 목소리가 연인이어도 말투만 그 관계에 맞추고 주제는 응원이다 |
| preset/custom(사용자 문구) | 사용자 말은 재작성하지 않는다. 번역 요청 시에만 네이티브 구어로 충실 번역. 사용자 입력은 DATA 로만 다룬다(인젝션 안전). 같은 언어는 Gemini 를 부르지 않는다 |

### 4.5 태그 정책 — **붙이지 않는다**(2026-09-30)

- **v4 Turbo 는 문장으로 결을 잡는다.** 같은 방향의 태그는 붙이든 빼든 차이가 음높이 2반음·음량 1dB 안쪽이고,
  텐션을 **올리는** 태그만 크게 먹으며(129→205Hz) **누르는** 태그는 거의 안 먹었다(스펙 `voice-and-message.md` §10).
  태그가 '차분을 망치는' 쪽으로만 효과가 있으니 쓰지 않는다. 결은 문장 모양으로 전한다 — 경쾌는 짧고 통통 튀는
  문장·가벼운 느낌표, 차분은 고른 문장·느낌표 거의 없이·신나는 낱말 없이(끝은 분명히 깨운다).
- **프롬프트에서 태그 지시를 전부 뺐다** — `DYNAMIC_SYSTEM_INSTRUCTION`·`dynamicAlarmTextPrompt`·`prerenderClipPrompt`
  (`WORDS ONLY`)·번역 `alarmTextPrompt`(대괄호를 새로 넣지 말 것). few-shot 예시의 대괄호도 뺐다(§4.9).
- **모델이 그래도 대괄호를 내면 벗긴다**(`stripAllTags`) — 거절하지 않는다. 지운 자리는 문장부호 앞에 공백을
  남기지 않는다. 태그 모양이 아닌 대괄호(`[다정하게]`)와 소괄호 지문(`(웃으며)`)은 벗길 수 없어 HARD 로 막는다.
- **없앤 것**: 예시 어휘(`TAG_EXAMPLES`), 저각성·공포·차분 금지 태그 거르기(`dropWakeUnsafeTags` 류), 문장마다 태그
  다시 앞세우기, 모드별·카테고리별 기본 태그, 등록 미리듣기의 `preview_tag`, 모델 웃음 규칙. 페이싱은 여전히
  `…`·쉼표로 만든다(SSML break 가 없고 v4 는 speed 도 무시한다).
- **남은 대괄호**: 사용자가 직접 친 것(건드리지 않는다)과 사용자가 친 글자 웃음을 바꾼 `[laughs]`(스펙 §9)뿐이다.
- **voice_settings**: stability 0.5 / similarity 0.8 둘만 보낸다(`TTS_VOICE_SETTINGS`). v4 계열은 style·speed·
  use_speaker_boost 를 조용히 무시한다.

### 4.6 길이 정책

목표는 한 줄 또는 두 짧은 문장(KO/JA 25~70자, EN 10~22단어), 하드캡 200자. v3 는 일관성을 위해 250자+를
권장했지만 수면관성 근거상 **짧은 쪽**을 택한다. 이 텐션은 패딩이 아니라 (1) 짧은 범위의 긴 쪽 지향
(2) stability=Natural (3) 문장부호 페이싱으로 헤지한다.

### 4.7 검증·재시도 (2단)

들쭉날쭉의 원인은 고온도 생성 + 정규식 binary 검증이 좋은 출력까지 통째로 폐기하고 고정 폴백으로
떨어뜨린 것이었다. 그래서 **폐기 대신 국소 수리**로 바꿨다.

- **HARD 차단**(→ 1회 재롤 → 회전식 폴백): 파싱 불가/메타 JSON, 200자 초과, 운세 PII 누설(생년월일·별자리),
  관계 라벨 누설·자기참조, 호칭 불일치(추정 가족호칭), 알람 시각/날짜 에코, 태그 모양이 아닌 브래킷·소괄호 지문,
  타깃 언어 불일치, 연인 톤의 '새 인연/연애운/질투'.
- **SOFT**(수용 + 자동 수리): 조사·띄어쓰기 슬립, 경미한 어체 슬립, 대괄호 태그(→ 벗긴다).
  과거의 '정중 어미 전량 reject' 는 SOFT 로 강등했다.
- **재시도**: 최대 1회, HARD/JSON 실패에만(공통 경로 1왕복 유지). temperature 는 보내지 않는다(Gemini 3 는
  무시한다). 2차 실패 시 **회전식 폴백**(mode+dateLabel 해시로 템플릿 회전 — 고정 단일 문구 금지).
- **JSON**: `responseSchema` 가 1차, brace-slice 파서는 최후 폴백으로 남긴다(flash 에서 responseSchema
  간헐 빈응답 대비).

### 4.8 페르소나·변주

- `relationship_label` 은 레지스터/온도/어휘만 구동하고 절대 발화하지 않는다. `listener_title` 은 그대로 쓴다.
- 화자 개성은 `voice_profiles.speech_style`(마이그레이션 #66)로 프롬프트에 주입한다. 초안이던
  `voice_gender`/`speech_formality`(#53)는 speech_style 로 대체돼 제거됐다.
- **변주는 경계한다**: freshness seed(dateLabel 등)로 opener·리듬·소소한 케어 디테일만 흔들고 골격은
  고정한다. 기상 실패율에 따른 각성 에스컬레이션은 soft-start 윤리와 충돌해 채택하지 않았고, 호출마다
  voice_settings 를 바꾸는 변주는 오디오 캐시 fan-out 이 폭증해 배제했다.

### 4.9 few-shot

언어별 3~5개를 주입한다(`DYNAMIC_FEW_SHOT`). 출력 계약이 `{text}`(낱말만)이므로 예시에도 대괄호가 없다 —
모델은 지시문보다 **예시를** 따른다(예시에 태그가 남으면 태그를 계속 낸다). 예시는 **살아 있는 모드**의 것만 유지하고,
인사가 아닌 예시에는 시간대 인사('좋은 아침'·'Morning'·'おはよう')를 넣지 않는다.

## 5. Gemini 실반영 전 게이트

`GOOGLE_VERTEX_DYNAMIC_TEXT_ENABLED=true` 로 켜기 전에 확인해야 하는 것 — 아래는 코드로 확정할 수 없고
사람이 듣고 판단해야 하는 **가설**이다.

1. **현지인 MOS**: KO/JA 원어민 각 10~20명, 샘플 8~12개. 자연스러움·관계 적절성·기상 의욕 평균 ≥ 3.8/5.
   특히 **JA 손주→조부모 タメ口 디폴트 수용도** — 거부감이 크면 정중 디폴트/토글을 다시 검토한다.
2. **v4 Turbo 청취**: 태그 없는 문장이 모드별 결을 싣는가, 남자 목소리 음높이·음량 변화(스펙 §10 「위험」)가
   폰 스피커에서 받아들일 만한가, 모드별 톤 체감.
3. **적대적**: 호칭/사용자 문구에 지시를 심어(관계 말해라, 시각 읽어라) 누설 게이트 우회 시도,
   JSON 깨뜨리기(코드펜스·중첩·메타) → HARD 100% 차단 → 재롤 → 회전 폴백 확인.

미달 시 문장 지시 강화, 정중 디폴트 전환, 프로바이더 라우팅 재검토가 대안이다.
