# 알람 편집기 — 시각 고르기 · 재생 방식 · 모달 형태

새 알람을 만들고 고치는 화면의 동작. **양 앱이 같아야 하는 것**만 적는다.

> 편집기의 **기본값**(직전 선택 유지) 규약은 `CLAUDE.md` 「알람 편집기 기본값 = 직전 선택
> 유지」에 있다. 목소리·문구를 **무엇으로 고를 수 있는가**는
> [voice-and-message.md](voice-and-message.md) 다. 여기는 **컨트롤이 어떻게 움직이는가**다.

## 1. 타임휠

한 칸 **92dp/pt**(글꼴 배율에 비례), 보이는 줄은 **3칸**, 가운데가 선택이다.
글자 크기는 선택 57 / 이웃 45 로 다르다 — 알파만으로 초점을 만들면 굴러가는 중에
어느 숫자가 골라질지 흐릿하다.

### 1-1. 튕기면 **굴러가서** 멎는다

손을 뗀 뒤 숫자가 **한 칸씩 지나가며** 감속해 멎는다. N칸을 즉시 대입하고 남은
오프셋만 되돌리면 **순간이동**이 되어, 중간 숫자가 하나도 안 보이고 몇 칸을 넘겼는지
알 수 없다(2026-08-11 지적 — iOS 가 그랬다).

| 값 | 규칙 |
| --- | --- |
| 붙기만 할 때 | 170ms |
| 튕겼을 때 | `190 + 42×칸수` ms, **230~720ms 로 조인다** |
| 한 제스처 최대 | **15칸** |
| 붙기 판정 | 반 칸(**0.45**)을 넘긴 쪽으로 |

⚠ **감속 곡선과 튕김 계수는 여기 없다 — 두 앱이 다르다.** 이 절은 같아야 하는 것만
적는데, 그 둘은 2026-08-15 에 각자 조율하기로 정했고 **들어오는 속도 값의 단위부터
다르다**(안드로이드 px/s, iOS 는 SwiftUI 가 주는 남은 이동 거리). 숫자와 이유는
「의도된 차이」 표에 있다 — **한쪽 숫자를 다른 쪽에 옮기지 말 것.**

⚠ **한 칸 굴러갈 때마다 톡 하고 알린다(햅틱).** 끌 때도, 놓고 굴러갈 때도, 숫자를
눌러 이동할 때도 같다 — 눈으로만 세지 않게 하는 것이 이 컨트롤의 절반이다. 사용자가
시스템에서 촉각 반응을 꺼 두었으면 아무 일도 일어나지 않는다(OS 가 판단한다).

⚠ **굴러가는 중에 손을 대면 그 자리에서 잡힌다.** 남은 칸은 넘기지 않는다.

⚠ **끌 때와 놓을 때의 방향이 같아야 한다.** 한때 놓을 때만 부호가 뒤집혀 있어, 반 칸
이상 끌어 올린 뒤 손을 떼면 값이 한 칸 도로 내려갔다 — 사용자에겐 "맞춰도 되돌아간다"
로 보인다.

### 1-2. 숫자를 누르면 **그 자리에서** 고쳐 쓴다

멀리 있는 값(7시 → 11시)을 92pt 씩 끌지 않아도 되게 하는 길이다.

- 가운데 숫자를 누르면 **그 숫자가 입력창이 된다.** 모달(알럿·다이얼로그)을 띄우지 않는다 —
  고치려는 숫자가 모달에 가리고 확인까지 두 번을 더 눌러야 한다(2026-08-11 변경).
- 입력창은 **비어서** 시작하고, 지금 값을 **흐리게(28%)** 깔아 둔다. 큰 글자 자리가 텅
  비면 무엇을 치는 자리인지 알 수 없다.
- **두 자리까지만** 받는다.
- 고쳐 쓰는 동안 **시·분 양쪽의 위아래 회색 숫자를 숨긴다.** 큰 입력 글자 옆에 흐린
  숫자가 남으면 지금 치는 값이 어느 것인지 헷갈린다. (오전/오후 칼럼은 그대로 둔다 —
  숫자가 아니고, 지금 무엇이 아닌지를 알려 준다.)
- 고쳐 쓰는 동안 **휠은 끌리지 않는다.**
- 확정: 키보드의 완료(iOS 는 숫자 키패드에 완료 키가 없어 **툴바**로 낸다) 또는 **포커스를
  잃을 때**(다른 칼럼·바깥 탭). 취소 버튼이 없으므로 포커스를 잃을 때 안 받으면 친 게
  조용히 사라진다.
- ⚠ **범위를 넘겨 쳐도 거절하지 않고 잘라서 넣는다**(99분 → 59분). 여기서 튕기면
  사용자는 왜 안 되는지 모른 채 같은 값을 다시 넣는다.
- 시 칼럼은 화면에 보이는 **12시간** 숫자를 받아, 지금 오전/오후를 **유지한 채** 24시간으로
  되돌린다. 오전/오후를 바꾸는 길은 그 칼럼 하나뿐이다.

⚠ **굴리는 값은 12시간이 아니라 24시간이다.** 1~12 를 굴리면서 오전/오후를 그대로 두면
11시에서 12시로 넘겨도 오전/오후가 바뀌지 않는다. 오전/오후는 `hour >= 12` 에서 **파생**된다.

## 2. 재생 방식 세그먼트

**두 칸뿐이다 — 목소리 / 알람.** '알람 + 목소리' 를 되살리지 말 것(`CLAUDE.md` 「재생
방식은 둘뿐」 참조).

- **목소리가 왼쪽**이고 새 알람의 기본값이다. 읽는 순서와 기본 선택이 어긋나면 첫 화면에서
  오른쪽 칸이 켜져 있어 무엇이 기본인지 흐려진다.
- 선택 표시는 **트랙 안에서 배경 하나가 미끄러져 옮겨간다.** 칸마다 색을 즉시 바꾸면
  전환이 툭 끊긴다.
- ⚠ **세그먼트 구현은 앱마다 하나다.** 트랙을 따로 그리는 두 번째 구현을 만들면, 선택
  표시를 옮길 때 한쪽만 고쳐져 **아무 칸도 켜져 보이지 않는다**(2026-08-10 실제 발생 —
  안드로이드에서 목소리·알람 둘 다 표시가 없었다).
- 저장된 값은 **정규화한 뒤** 비교한다. 옛 값('알람 + 목소리')을 날것으로 비교하면 어느
  칸과도 안 맞아 선택 표시가 사라진다.
- ⚠ **'알람' → '목소리' 로 바꾸면 목소리(TTS) 갈래로 들어가고, 문구가 비어 있으면 직전
  선택을 잇는다**(2026-09-29). 알람 전용 알람은 소스를 '직접 녹음' 으로, 문구 필드를 비워
  (iOS 는 테마만 남겨) 저장하므로 그대로 두면 녹음 카드(iOS)나 **빈 직접 입력**(안드로이드)이 떴다. 잇는 규칙과
  예외는 [voice-and-message.md](voice-and-message.md) §4 「적용 대상은 새 알람뿐」.
  빈 직접 입력으로 저장을 누르면 **요청 전에** 알럿으로 막는다(`MANUAL_TEXT_MISSING`).

## 2-1. 반복 자리의 '날짜 지정(한 번)' (2026-10-26)

반복 요일 칩 아래에 **'날짜 지정'** 스위치가 있다. 켜면 그 알람은 고른 날짜에 한 번만 운다 — 규칙 전문(저장값·
시간대·울림·서버)은 [alarm-lifecycle.md](alarm-lifecycle.md) §4 다. 여기는 컨트롤만 적는다.

- 스위치를 켜면 요일 선택이 모두 풀리고(`repeatDaysMask = 0`), 날짜는 **지금 고른 시각이 아직 오지 않았으면 오늘,
  지났으면 내일**로 시작한다. 시간대는 그 순간의 기기 시간대다.
- 켜져 있는 동안 스위치 아래에 **날짜 줄**이 있다 — 누르면 날짜 고르기 폼 시트(§4 의 두 번째 형태 — 좌 `취소` ·
  가운데 제목 · 우 확정)가 뜬다. 오늘보다 앞의 날은 고를 수 없다.
- 요일 칩을 하나라도 누르면 날짜 지정이 꺼진다(둘은 배타적이다). '공휴일에는 끄기' 는 요일을 고른 알람에만 있으므로
  날짜 지정 중에는 보이지 않는다.
- 위의 요약 줄은 반복 알람이면 요일, 날짜 알람이면 **그 날짜**(오늘·내일이면 그 말을 붙인다)를 말한다.
- 이미 저장된 날짜 알람을 열면 그 날짜·시간대를 그대로 쓴다 — 날짜를 다시 골라도 **시간대는 저장된 값**이다(사용자가
  확인한 값). 기기 시간대와 다르면 날짜 줄 아래에 "<시간대> 기준 · 이 기기 시각 <날짜 시각>" 을 쓴다. 스위치를 껐다
  켜면 지금 기기 시간대로 새로 시작한다.
- 저장을 누르면 지난 시각·같은 시각 알람을 **그 자리에서** 다시 재 알럿으로 막는다(alarm-lifecycle.md §4-3). 버튼은
  죽이지 않는다.
- 날짜 지정은 직전 선택으로 이어받지 않는다 — 새 알람은 언제나 꺼진 채 열린다.

## 3. 음성 출력

- **목소리 크기**: 10~100%, **10단위**. 하한 10% 는 두 앱이 같아야 한다 — 한쪽이 30% 로
  막으면 다른 앱에서 맞춘 알람이 다른 크기로 울린다. 0 은 슬라이더로 만들 수 없다.
- ⚠ **'끌 때까지 반복' 컨트롤은 두지 않는다**(2026-08-27 지시, 2026-09-02 스펙 정정).
  목소리는 **항상 반복**한다 — 한 번 나고 그치면 그것은 알림이지 알람이 아니다.
  저장값(`voiceRepeat`)은 계속 true 로 왕복시키되 화면에는 컨트롤이 없다(양 앱).
  (이 문서는 없앤 스위치를 2026-09-02 까지 요구하고 있었다. 회귀 테스트
  `AlarmEditDraftTests` 가 반대편을 고정하고 있었던 것이 근거다.)
- iOS 에는 **알람 음량 슬라이더를 두지 않는다** — AlarmKit 이 OS 톤을 소유해 제어할 수
  없다(「의도된 차이」).

## 4. 모달은 **세 형태**뿐이다

| 무엇 | 형태 | 닫는 법 |
| --- | --- | --- |
| 목록에서 하나 고르기 | **바텀시트** — 좌우 여백 0, 위 모서리만 둥글다, 좌측 정렬 22 Bold 제목 | 고르면 닫힘 · 스크림 탭 · 아래로 끌기 |
| 입력이 여러 개인 폼 | **바텀시트 + 상단바** — 좌 `취소` · 가운데 제목(17 SemiBold) · 우 확정 | 취소 · 스크림 탭 · 아래로 끌기 |
| 확인 한 번 | **시스템 알럿**(iOS) / `IosAlertDialog`(안드로이드) | 액션 |

- ⚠ **선택 시트에 '닫기' 버튼을 두지 말 것.** 고르면 어차피 닫히므로 취소와 같은 일을
  하는 두 번째 액션이 된다. 2026-08-11 에 목소리 고르기 시트만 상단바 + '닫기' 였다.
- ⚠ **폼을 가운데 카드 + X 로 되돌리지 말 것.** 그건 안드로이드·웹 문법이다. 아이폰의
  폼 모달은 시트로 올라오고 상단바에 좌 `취소` · 가운데 제목 · 우 확정을 둔다(애플 캘린더
  '새로운 이벤트'). 2026-08-11 에 양쪽 다 이쪽으로 통일했다.
- ⚠ **확정 버튼을 본문 아래에 두지 말 것.** 본문이 길어 스크롤되면 저장이 화면 밖으로
  밀린다 — 상단바는 항상 보인다. 그래서 폼의 초안 상태는 **모달 밖**에 둔다(안에만 있으면
  상단바가 그 값을 볼 수 없다).
- 시트 높이는 **내용만큼**, 화면의 **90%**(`BottomSheetMetrics.maxFraction`)를 넘으면 그 안에서 스크롤한다.
  (2026-08-13 에 0.5 → 0.9. 낮추면 짧은 시트는 어차피 자연 높이라 그대로이고 **긴 목록만 반쪽으로 잘린다**.)
  ⚠ 상수를 더해 계산하지 말 것 — 글꼴·기기마다 달라 맞출 수 없다. **스크롤 안의 내용**과
  **스크롤 밖 머리말**을 각각 재서 더한다(머리말을 빼먹으면 마지막 행이 잘린다).
- 행 규격은 **가로 20 · 세로 10 · 최소 높이 56**. 최소 높이는 패딩을 **포함**한다 —
  순서를 뒤집으면 76 이 되어 다른 시트보다 20 이나 높아진다.

### 4-1. 알럿 규격 — **실측값이다**

iOS 26 의 `UIAlertController` 를 시뮬레이터에서 재서 얻은 값이다(2026-08-11).
애플은 알럿의 픽셀 규격을 공개하지 않으므로 **블로그 숫자를 베끼지 말고 이 표를 쓴다.**
값이 의심되면 `AlarmTalkUITests/SystemAlertMetricsUITests` 와
`DeleteAccountAlertUITests` 를 돌려 다시 잰다.

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 알럿 폭 | **320 고정** | 화면이 커져도 그대로. 390/402/440pt 기기 셋에서 전부 320이었다 |
| 모서리 | 약 34 | 14 는 iOS 7~18 값이다 |
| 좌우 글자 여백 | 30 | 글자 폭 260 |
| 제목 위 여백 | 22 | |
| 제목 → 본문 | 7 | |
| 본문 → 액션 | 20 | |
| 액션 높이 | **48** | 44 아니다 |
| 액션 여백 | 좌우·아래 16, 사이 8 | |
| 액션 모양 | **채운 캡슐** | ⚠ 구분선 없음. 구분선으로 나눈 텍스트 버튼은 iOS 18 이하다 |
| 파괴적 액션 | 글자만 빨강 | 채움색은 다른 액션과 같다 |
| 제목 글자 | 17 | |
| 본문 글자 | **14.5** | ⚠ 13 이 아니다 — 그려진 글리프를 재서 확인했다 |
| 자간 | **0** | ⚠ SF Pro 트래킹(-0.4 등)을 쓰지 말 것. 한글이 붙어 안 읽힌다 |
| 본문 정렬 | 한 줄이면 가운데, **여러 줄이면 왼쪽**(제목도 함께) | |

⚠ **폰트는 "선언한 크기" 가 아니라 "그려진 글리프" 로 비교한다.** 오래 "본문 13" 으로
알고 썼는데 실제로는 15% 작게 그려지고 있었고, 그래서 같은 문장이 아이폰 3줄 /
갤럭시 2줄로 갈렸다. 줄 수가 다르면 크기가 다른 것이다.

⚠ **애플 글꼴은 안드로이드에 못 쓴다.** SF Pro 도, iOS 가 한글에 쓰는 Apple SD Gothic Neo
도 애플 플랫폼 전용 라이선스다. 안드로이드는 Pretendard 를 쓴다 — 그 자리를 메우려고
만들어진 글꼴이라 선택은 맞고, 맞춰야 할 것은 **자간과 실제 글리프 크기**다.

## 5. 목소리 카드 · 세부 설정

- ⚠ **'삭제된 목소리' 배너를 두지 않는다**(2026-09-29 지시, 양 앱). 목소리를 잃은 알람은
  모달이 이미 알린다 — 앱에 들어올 때 강등 안내(무료 전환·다른 기기의 삭제·제자리 교체), 직접 지울
  때 삭제 확인. 편집기에 같은 말을 또 띄우면 이미 읽은 안내가 편집할 때마다 경고처럼 남는다.
- 그 목소리로 **저장을 누르면** 알럿이 말한다: "목소리를 골라주세요 / 고른 목소리를 지금은 쓸
  수 없어요. 다른 목소리를 골라 주세요." 버튼은 죽이지 않는다(`CLAUDE.md` 「잠그는 것은
  '저장 중' 일 때뿐이다」). 정리 중인 교체 목소리는 이 갈래가 아니라 "아직 준비 중이에요" 로
  따로 말한다.
  - **테마를 골랐어도 막는다.** 테마 클립은 그 목소리의 클립이라 목소리가 사라지면 받을 수 없다
    (서버 오디오 라우트가 삭제·접근 불가 목소리를 거절한다). 판정은 테마 갈래보다 **먼저** 한다 —
    안드로이드 `editorSaveBlockReason` 이 `usableTtsProfileIds` 를 테마 갈래 앞에서 보는 것과 같다.
  - 삭제·미준비 목소리는 기존 알람의 음원을 그대로 쓸 수 있으면(시각만 고치는 재저장) 막지 않는다.
  - ⚠ **무료 플랜 잠금은 음원이 있어도, 테마를 골랐어도 막는다.** 판정은 고른 목소리가 기본
    목소리인가 하나다. 막는 곳은 **앱**이다 — 안드로이드는 편집기 판정 뒤의 `voiceAlarmAllowed`
    (`usesFreeSystemVoiceAlarm` — 테마와 무관하게 `isSystemVoiceId` 부터 본다)가 막는다. (2026-10-29 전에는 서버
    `PATCH /alarm` 도 저장된 값 그대로의 유료 목소리를 403 `VOICE_FEATURE_REQUIRES_PAID_PLAN` 으로 거절했다 — 서버 알람
    사본과 함께 없어졌다, [alarm-lifecycle.md](alarm-lifecycle.md) 「서버에는 알람이 없다」. 유료 목소리 음원의 **재생**은
    지금도 오디오 라우트가 막는다.)
- **세부 설정 카드의 행 순서는 알람음 → 진동**이다(2026-09-29 지시, 안드로이드). 알람음 행은
  재생 방식이 '알람' 일 때만 있으므로, 행 사이 구분선은 **알람음 행에 붙어** 함께 나타나고
  사라진다. iOS 에는 진동 행이 없다(AlarmKit 이 진동을 소유한다 — 「의도된 차이」).
- **진동 값은 안드로이드 목록 18종이다**(2026-10-12). 1.3 앱은 알람을 서버로 올리지 않는다(2026-10-29 — 서버에는 알람이
  없다). 서버의 같은 목록(`VIBRATION_PATTERNS`)은 옛 앱(1.2.16)의 올리기를 검사하는 데만 쓴다 — 그 앱이 고른 패턴이
  400 `INVALID_VIBRATION_PATTERN` 을 맞지 않게. (2026-10-12 전에는 서버가 `default`·`strong`·`none` 셋만 받아 그 밖의 패턴을
  고른 알람이 동기화마다 400 이었다(ALARMTALK-ANDROID-14) — 알람은 폰에서 울렸지만 서버 사본이 갱신되지 않았다.) iOS 는 진동
  화면이 없지만 같은 18종 enum 으로 읽고 편집기 저장 때 그 값으로 다시 적는다 — enum 에 없는 값은 '기본' 으로 덮인다. 그래서
  패턴을 더하면 **세 곳**(안드로이드·iOS·서버)을 같이 고친다 — `scripts/check-vibration-patterns.py`(CI lint)가 세 목록을
  비교한다(서버 목록은 옛 앱 호환 경로를 지울 때 함께 뺀다).

## 6. 저장 버튼 — 파일을 읽는 확인은 **메인 밖에서, 저장 잠금 안에서** (안드로이드, 2026-10-11)

저장 버튼의 규칙(버튼은 '저장 중' 일 때만 잠그고, 저장할 수 없는 사유는 누르면 알럿으로 말한다 —
`CLAUDE.md` 「저장 뒤 검은 화면」)은 그대로다. 바뀐 것은 **파일을 읽는 확인이 어디서 도는가**다.

- **같은 문구의 오디오가 폰에 있는가**(직접 입력 재사용 — [voice-and-message.md](voice-and-message.md)
  §8 「저장할 때의 순서」의 ①)는 저장을 누른 뒤 **IO 에서** 찾는다 — 별칭 `.meta` 읽기 · 파일 찾기 ·
  길이 재기. 예전에는 누르는 순간 메인 스레드에서 했다(2026-10-10 Sentry 조사).
- **찾는 동안이 곧 '저장 중' 이다.** 버튼이 잠기고(스피너) 그동안 들어온 두 번째 탭은 **버린다** —
  쌓아 두면 같은 알람이 두 번 저장되고 완료 콜백이 두 번 팝해 검은 화면이 된다. 찾았으면 서버를 부르지
  않고 곧바로 저장하고(뷰모델의 '저장 중' 으로 이어진다 — 잠금이 풀리는 틈이 없다), 못 찾았으면 다음
  단계로 간다. 찾다 실패하면 '없다' 로 보고 다음 단계로 간다.
- ⚠ **저장을 누른 뒤 바꾼 것은 그 값으로 저장한다**(2026-10-29 오너 "저장을 누르면 바뀐걸로 되어야"). 잠기는 것은
  저장·취소 버튼뿐이라 찾거나(로컬 확인) 만드는(생성·테마 클립 받기) 몇 초 동안 시각·문구·목소리를 고칠 수 있다.
  결과를 그대로 이으면 누른 순간의 값으로 만든 오디오가 바뀐 상태와 섞이거나(예전 생성 갈래는 누른 순간의 목소리·
  문구로 **덮어** 저장했다) 바꾼 것이 사라진다. 그래서 누른 순간의 초안과 지금 초안이 같을 때만 잇고, 다르면 결과를
  잇지 않은 채 **잠금이 풀린 뒤 지금 화면 값으로 저장을 다시 돈다**(`resaveAfterChange`). 만든 결과는 폰에 남아(입력
  키 화살표) 같은 입력이면 다시 써서 더 세지 않는다. 예전 로컬 확인 갈래(Codex #879)는 다르면 버리고 다시 누르기를
  기다렸다. 시각을 바꿔도 만드는 중인 음성을 **취소하지 않는다** — 끝난 뒤 바뀐 것을 보고 새 시각으로 다시 저장한다
  (취소하면 서버가 이미 센 생성을 잃고 다시 눌러야 했다).
- **초안이 뷰모델로 넘어간 뒤(마지막 저장)에는 편집기 입력을 막는다** — 그때 바꾼 것은 저장되지 않은 채 편집기만
  닫힌다(날씨 알람은 조건을 푸느라 몇 초 걸린다). 입력 중이던 칸도 닫는다.
- **iOS 도 같다**(2026-10-29 두 앱 비교). `AlarmEditorSheet.saveFlow` 가 누른 순간의 입력(`EditorSaveInputs` — 초안 +
  목소리·문구·테마·날씨·운세·녹음)을 잡아 두고, 음원을 준비한 뒤 알람 행을 만들기 직전에 지금 값과 견준다. 다르면 지금
  값으로 한 번 더 돈다 — 목소리·문구 쪽이 바뀌었으면 준비한 음원을 버리고, 시각·요일만 바뀌었으면 음원은 그대로 쓰고 시각만
  다시 잰다. 다시 도는 것은 두 번까지이고, 행을 만든 뒤(날씨 조회·AlarmKit 예약)에는 편집을 막는다(`committingSave`). 예전
  iOS 는 누른 순간의 목소리·문구로 만든 음원을 그대로 저장했고, 날짜 알람은 옛 시각으로 예약됐다.
- **오프라인 판정(`OFFLINE_NEW_MESSAGE`)도 그 확인으로 한다** — §8 의 ②. 저장 사유를 세는 자리는 더 이상
  파일을 읽지 않는다. 예전에는 오프라인 + 직접 입력이면 화면이 다시 그려질 때마다 같은 파일을 읽었다.
  그래서 이 알럿은 이제 저장 흐름 안에서, 권한 확인 **뒤에** 뜬다 — 문구와 판정식(직접 입력 +
  오프라인 + 폰에 없음)은 같다.
- 나머지 사유(목소리·날씨·운세·빈 직접 입력·클립 과도기)는 메모리 값만 보므로 그대로 누르는 순간 판정한다.

## iOS 중복 시각 알람 교체의 실패 처리

새 알람의 저장·예약이 성공한 뒤 충돌 알람을 **차례로** 지운다(예약 취소 → 행 삭제 — 기기의 예약과 행뿐이다. 서버에는
알람이 없다, 2026-10-29). 하나라도 실패하면 거기서 멈추고 그 행과 아직 처리하지 않은 충돌을 보존하고
새 저장을 롤백한다. 이미 삭제에 성공한 앞선 충돌은 되살리지 않는다. 편집 중이던 기존
알람의 예약은 교체 정리가 끝나기 전에는 취소하지 않는다. 성공 안내·선택 기억·저장 사건은
정리 완료 뒤에만 기록한다.
충돌 삭제 중 계정이 바뀌면(자동 401 포함) 그 삭제는 실패로 보고 임시 저장을 롤백한다. 저장 당시 소유자·내용·
예약 핸들이 여전히 같은 행인지 확인해 기존 편집본/예약을 복원하거나 신규 행을 지운다.
현재 인증 여부만으로 복원을 생략하지 않는다. 동시 삭제·끄기·다른 소유자/예약으로 교체된
행은 덮어쓰지 않는다(같은 편집본인지 볼 때 동기 칸 — `remoteAlarmId`·`syncState` 등 — 은 보지 않는다).
(2026-10-29 전에는 **서버 삭제 성공을 확인한 행만** 로컬에서 지웠고, 정리 대기 중인 새 내용을 서버 push 대상에서 뺐다 —
서버 알람 사본을 지워 그 단계가 없다.)

## 의도된 차이

| 무엇 | 왜 |
| --- | --- |
| iOS 에 알람 음량 슬라이더 없음 | AlarmKit 이 OS 톤을 소유한다. 못 움직이는 컨트롤을 두면 값을 바꿔 보고 저장하고 확인하기를 반복하게 된다 |
| iOS 세부 설정에 진동 행 없음 | 같은 이유 — AlarmKit 이 알람 진동을 소유해 고른 패턴이 실제 알람에 닿지 않는다. 그래서 iOS 카드에는 알람음 행 하나뿐이고, 목소리 모드에서는 카드를 통째로 감춘다 |
| 확인 알럿의 껍데기 | iOS 는 시스템 `.alert`, 안드로이드는 그걸 흉내 낸 `IosAlertDialog`. iOS 에서 껍데기를 새로 만들면 오히려 원본에서 멀어진다 |
| 숫자 입력 확정 키 | iOS 숫자 키패드에는 완료 키가 없어 **키보드 툴바**로, 안드로이드는 IME 의 **Done** 으로 |
| 타임휠 **정착 곡선·튕김 판정** | **곡선**: 안드로이드 `TimeWheelEasing = (0.3, 0.6, 0.3, 1)`(`ui/editor/DraggableTimeWheelColumn.kt`) / iOS `TimeWheelSettle.ease` 의 `(0.16, 1, 0.3, 1)`. **튕김**: 안드로이드는 **px/s** 를 받아 최소 `칸높이 × 4.2/s`·칸수 `(속도/칸높이) × 0.09`(`flingStepsFor`), iOS 는 SwiftUI 가 주는 **남은 이동 거리**를 받아 최소 `칸높이 × 0.63`·칸수 `(거리/칸높이) × 0.8`(`TimeWheelPicker.snapStep`). 저사양 실기(SM-A325N) 프레임 예산에 맞춰 2026-08-15 에 **안드로이드만** 0.12 → 0.09 로 낮췄다. 같은 기기 조건도 아니고 들어오는 양 자체가 다른 값이라 **맞추지 않는다** — 한쪽 숫자를 그대로 옮기면 안 된다 |
| 알럿을 **바깥 탭으로 닫기** | iOS 는 **안 된다** — 시스템 알럿은 명시적 선택을 요구하고 그 동작을 바꾸는 공개 API 가 없다. 안드로이드는 닫힌다(플랫폼 관례). 2026-08-11 에 확인하고 **각자 표준을 따르기로 정했다** — 맞추려면 iOS 시스템 알럿을 버리고 직접 그려야 하는데, 그건 우리가 맞춰 온 원본을 버리는 것이다 |
