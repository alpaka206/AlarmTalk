# 동작 스펙 — 세 구현의 **단일 출처**

이 폴더는 AlarmTalk 이 **무엇을 하는가**를 정한다. 안드로이드·iOS·백엔드 셋 다 여기를 따른다.

## 왜 만들었나

플랫폼마다 문서를 따로 두니 같은 규칙이 세 벌로 갈라졌고, 갈라진 줄 아무도 모른 채
한쪽만 고쳐 왔다. 실제로 이렇게 어긋났다:

- 기본 목소리 제한을 안드로이드는 `freeVoiceTier **||** 시스템보이스`, iOS 는 `**&&**` 로
  써서, iOS 에서만 말할 수 없는 문구를 저장할 수 있었다(2026-08-07).
- 목소리 게이트를 양쪽 다 2분기로 써서 **유료 사용자에게 '로그인이 필요해요'** 를 띄웠다.
- iOS 에 「기본 목소리 고르기」 화면이 남아 있었는데, 안드로이드 대응 화면은 **다운로드
  진행 화면**이었다. 소스 주석은 "안드로이드 미러" 라고 주장하고 있었다.

셋 다 "어느 쪽이 맞는가" 를 적어 둔 곳이 없어서 생겼다.

## 규칙

1. **여기가 규칙이고, 코드는 구현이다.** 구현이 스펙과 다르면 **구현이 틀린 것**이다.
2. **동작을 바꾸려면 이 문서를 먼저 고친다.** 코드만 고치고 문서를 두면 다음 사람이
   (사람이든 AI 든) 옛 규칙을 근거로 되돌린다.
3. **각 문서에는 「구현 지도」 표가 있다.** 규칙 한 줄이 세 구현의 어디에 사는지 적는다.
   한 곳만 고치는 사고를 막는 장치다.
4. **소스 주석의 "안드로이드 미러" 주장을 근거로 삼지 말 것.** 근거는 이 스펙이다.
   주석은 썩는다 — 실제로 여러 건이 틀려 있었다.
5. **플랫폼 차이는 「의도된 차이」 절에 적는다.** 거기 없는 차이는 버그다.
