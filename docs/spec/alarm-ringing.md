# 알람이 울릴 때

> **단일 출처.** 구현이 이것과 다르면 구현이 틀린 것이다. → [README](README.md)

## 1. 무엇이 뜨는가 — 기기 상태가 가른다

| 기기 상태 | 뜨는 것 | 왜 |
| --- | --- | --- |
| 화면 꺼짐 / 잠김 | **전체 울림 화면** | 잠금화면을 덮지 않으면 해제할 방법이 없다 |
| 화면 켜짐 + 잠금 해제 (= 앱을 쓰는 중) | **알림(헤드업)** | 쓰던 화면을 통째로 뺏지 않는다 |
| 화면 켜짐인데 **알림이 못 뜨는 상태** | **전체 울림 화면** | 소리만 나고 해제 UI 가 없는 상태를 만들지 않는다 |

⚠ **세 번째 줄이 핵심이다.** "포그라운드면 알림" 이 아니라 **"알림이 실제로 보일 때만
알림"** 이다. 알림 권한 없음·채널 강등·DND 억제면 배너가 안 뜨는데, 그때 전체화면을
생략하면 **소리는 나는데 끌 수가 없다.**

알림이 뜰 수 있는지 판정에 들어가는 것:
1. 알림 권한이 켜져 있는가
2. 울림 채널 importance 가 HIGH 이상인가 (사용자가 강등할 수 있다)
3. 방해금지(DND)가 시각 알림을 억제하지 않는가
   - 채널이 DND 우회면 무조건 가능
   - `ALL`(DND 끔) / `ALARMS`(알람만 허용) → 가능
   - `PRIORITY` → 정책이 알람 카테고리를 허용할 때만
   - `NONE`·미상 → 억제로 본다

판정을 못 하면(권한 부족으로 정책을 못 읽는 등) **보수적으로 전체화면**을 띄운다.

## 2. 어떻게 꺼지는가

| 사용자 행동 | 결과 |
| --- | --- |
| 알림의 '해제' 누름 | 알람 종료 |
| 알림의 '다시 알림' 누름 | 스누즈 |
| **알림을 스와이프로 지움** | **알람 종료** (소리·진동 함께 멈춤) |
| 전체 울림 화면에서 해제 | 알람 종료 |

⚠ **스와이프 제거를 '무시'로 두지 말 것.** `setOngoing(true)` 로도 targetSdk 34+ 에서는
스와이프를 막지 못한다(Android 13 의 FGS 스와이프 허용 + 14 의 ongoing 무력화). 삭제
인텐트가 없으면 **배너만 사라지고 톤·목소리·진동이 무기한 계속된다.** 그래서 스와이프도
해제로 취급한다.

단, **폴백 경로에는 삭제 인텐트를 걸지 않는다.** 포그라운드 서비스를 못 띄운 상황이라
`getService` 가 실패할 수 있고, 그 경로의 소리는 채널 사운드 1회성이라 '무한히 울림'
증상 자체가 없다.

## 3. 소리 규약

- **첫 샘플부터 제 크기.** 페이드인을 넣지 않는다 — TTS 한 문장이 램프 구간보다 짧아
  문장 전체가 작게 들린다.
- **음량 슬라이더는 곱하지 않는다.** 목소리 슬라이더 = 목소리 게인, 알람음 슬라이더 =
  톤 게인. 곱하면 알람 음량을 낮출 때 못 줄이는 톤은 그대로인 채 목소리만 묻힌다.
- **미리듣기는 울림과 같은 스트림**이어야 한다(`USAGE_ALARM`). 기본값(`USAGE_MEDIA`)이면
  같은 설정인데 크기가 다르게 들려, 폰으로 검증하는 사람이 문제를 영영 못 잡는다.
- **안드로이드는 울릴 때 기기 알람 볼륨을 맞추고, 끝나면 되돌린다.** 되돌리기가 그
  클래스의 존재 이유다 — 올리기 **전에** 원래 값을 적어 두고, 프로세스가 죽어도 다음
  실행이 되돌린다.

## 4. 권한이 없으면 어떻게 되는가 — **"안 울린다" 고 쓰지 말 것**

셋 중 무엇이 빠져도 **알람은 울린다.** 안 울린다고 쓰면 사용자가 멀쩡히 울릴 알람을
없는 것으로 믿고 다른 알람을 또 맞춘다.

| 빠진 권한 | 실제 결과 | 어떻게 말하나 |
| --- | --- | --- |
| 알림 | 울린다. 알림·헤드업이 안 뜰 뿐 — 그때는 울림 화면을 직접 띄운다 | "알람 알림이 뜨지 않아요" |
| 정확한 알람 | 울리되 수 분 늦을 수 있다 | "제때 울리지 않을 수 있어요" |
| 잠금 화면 | 소리는 나되 잠금 화면을 못 덮는다 | "잠금 화면에 뜨지 않아요" |

## 5. 의도된 플랫폼 차이

| 항목 | 안드로이드 | iOS | 이유 |
| --- | --- | --- | --- |
| 울림 화면을 누가 그리나 | **우리** (`RingingActivity`) | **시스템** (AlarmKit ALERT UI) | AlarmKit 이 소유해 우리가 못 그린다 |
| 전체화면/알림 분기 | 위 표대로 우리가 판정 | **판정하지 않는다** — 시스템이 정한다 | 위와 같은 이유 |
| 알람 음량 슬라이더 | 있다 | **없다** | AlarmKit 이 OS 톤을 소유해 제어 불가. 못 움직이는 컨트롤은 두지 않는다 |
| 정보량 보정 | — | alert 제목·Live Activity 에 **시각**을 넣는다 | 우리가 화면을 못 그리는 대신 |

## 검증 방법

⚠ **시뮬레이터·에뮬레이터로는 이 문서를 검증할 수 없다.** 정확한 알람·doze·잠금화면
전체화면·AlarmKit ALERT 는 실기기에서만 실제 동작을 보인다. 화면 배치나 문구는
시뮬레이터로 보되, **울리는가·꺼지는가는 반드시 실기기**로 확인한다.
