# 알람이 울릴 때

> **단일 출처.** 구현이 이것과 다르면 구현이 틀린 것이다. → [README](README.md)

## 1. 무엇이 뜨는가 — **언제나 전체 울림 화면**

기기 상태를 가리지 않는다. 화면이 꺼져 있든 켜져 있든, 잠겨 있든 풀려 있든 **전체 울림
화면을 띄운다**(2026-09-09 지시).

⚠ **예전에는 '앱을 쓰는 중이면 헤드업 배너' 였다 — 되돌리지 말 것.** 배너가 실제로
그려지는지를 **앱은 알 수 없다.** 알림 권한·채널 importance·DND 를 전부 통과해도
SM-A325N(Android 13)에서는 알림창에만 쌓이고 위에 뜨지 않았다(2026-09-09 실기기. 같은
판정을 통과한 S23 Ultra 는 떴다). 즉 판정이 "뜬다" 고 말한 기기에서 **해제 UI 가 하나도
없었다.** 안드로이드에는 "이 알림이 배너로 떴는가" 를 돌려주는 API 가 없으므로, 물어볼 수
없는 것을 근거로 화면을 생략하지 않는다.

**대신 잃는 것**: 폰을 쓰는 중에도 화면을 통째로 뺏는다. 통화·타이핑 중에도 그렇다.
알고 택한 쪽이다 — 알람이 울리는데 끌 방법이 없는 것보다 낫다.

⚠ **'항상' 은 최선 노력이지 보장이 아니다.** 다른 앱이 전경일 때의 액티비티 시작은 OS
재량이고(`SYSTEM_ALERT_WINDOW` 를 쓰지 않는다) 막히면 예외조차 없다. 그래서 울림 알림의
`setFullScreenIntent` 는 **폴백으로 그대로 둔다** — 그게 이 경로가 실패했을 때 남는 유일한
해제 표면이다. 겹침이 보기 싫다고 **채널을 강등하거나 FSI 를 떼지 말 것**(폴백이 사라진다).

## 2. 어떻게 꺼지는가

| 사용자 행동 | 결과 |
| --- | --- |
| 알림의 '해제' 누름 | 알람 종료 |
| 알림의 '다시 울리기' 누름 | 다시 울림 — **꺼져 있으면 버튼을 붙이지 않는다**(붙여 놓고 종료로 마감하면 누른 뜻과 반대다) |
| **알림을 스와이프로 지움** | **알람 종료** (소리·진동 함께 멈춤) |
| 전체 울림 화면에서 해제 | 알람 종료 |
| **울림 화면을 벗어남**(홈·최근앱·앱 전환·**전화 수신**·전원 버튼) | 알람 종료 — **잠금 여부와 무관하다** |

⚠ **아무도 알람을 멈춰 주지 않는다.** 울림에는 타임아웃이 없다 — `RingingService` 는
사용자가 끄거나 화면을 벗어날 때까지 계속 운다. 자동으로 멎는 유일한 경우는 그 알람을
지우거나 끄는 것이다(`AlarmRepository.stopRingingIfThisAlarm`). **'N분 뒤 자동 종료' 를
넣지 말 것** — 못 일어난 사람의 알람이 혼자 꺼진다.

⚠ **'벗어남' 을 잡는 지점은 하나다: `Activity.onStop`.** 홈·최근앱·앱 전환·전화 수신·전원
버튼이 전부 그 하나로 온다. 전원 버튼을 따로 잡으려 하지 말 것 — `KEYCODE_POWER` 는 시스템이
먼저 삼켜서 앱에 오지 않고, `ACTION_SCREEN_OFF` 를 따로 받아도 같은 사건을 두 번 세는 것이다.
(화면이 켜져 있었는지는 판정에 쓰지만, 그건 `onStop` 시점에 `PowerManager` 로 **읽는** 것이지
별도 경로가 아니다.)

⚠ **기본은 끄는 것이다 — 잠금화면이든 아니든.** 알람이 울린다고 **전화를 못 받게 할 수는
없다.** 통화 화면이 덮으면 화면은 켜진 채 `onStop` 이 오고, 그건 언제나 사람이 한 일이다.
전원 버튼도 같다.

⚠ **예외는 하나뿐이고, 지우지 말 것: 잠긴 기기에서 뜬 직후(3초) 꺼진 화면.**
사람이 그 사이에 반응하기는 어렵고, 그 시간대에 잠긴 폰의 화면을 끄는 것은 대개
**가방·주머니·플립커버**다. 이걸 '나갔다' 로 읽으면 **자는 사람이 못 일어난다** — 이 앱에서
가장 나쁜 결과라, 모르면 울리는 쪽으로 기운다. 판정에 쓰는 축은 둘뿐이다:

| 어떻게 떠났나 | 잠긴 채였나 | 결과 |
| --- | --- | --- |
| 화면이 켜진 채(전화·홈·앱 전환) | 상관없음 | **끈다** — 유예 없음 |
| 화면이 꺼짐(전원 버튼·커버) | 잠금이 풀린 적 있음 | **끈다** — 유예 없음 |
| 화면이 꺼짐 | 잠긴 채 + 뜬 지 3초 안 | **안 끈다**(기계로 본다) |
| 화면이 꺼짐 | 잠긴 채 + 3초 지남 | **끈다** |

**알고 택한 대가**: 잠결에 전원 버튼을 누르면 알람이 끝난다. 끄기 슬라이더에 일부러 넣은
마찰(관성·플릭 없음)보다 쉬운 길이 생긴 것이다. 요청된 동작이다.

사용 기록에는 `detail` 로 남긴다 — 화면이 꺼져서 떠났으면 `"screen_off"`, 다른 화면으로
갔으면 `"left_screen"`. **오탐 가능성이 있는 유일한 해제**라, 구분되지 않으면 오탐이 나고
있어도 알 수 없다.

⚠ **울림 화면을 벗어나는 것(홈·최근앱·제스처)은 막을 수 없고, 막지 않는다.** 일반 앱은
HOME 을 가로챌 수 없다 — 유일한 수단인 화면 고정(`startLockTask`)은 시스템 확인 다이얼로그를
먼저 띄우고 사용자가 언제든 빠져나갈 수 있어 목적을 이루지 못하며, 해제 경로 하나만 빠뜨려도
알람이 끝난 뒤 **폰에 갇힌다.** 막는 대신 **나가는 것을 뜻 있게** 만들었다 — 위의 '벗어남 = 해제' 가 그 답이다.
잠금화면에서 뜬 알람은 나가도 계속 운다(소리·진동의 주인이 액티비티가 아니라 **포그라운드
서비스**다). 뒤로가기만 삼킨다(`blockBackNavigation`).

⚠ **스와이프 제거를 '무시'로 두지 말 것.** 삭제 인텐트가 없으면 **배너만 사라지고
톤·목소리·진동이 무기한 계속된다.** 그래서 스와이프도 해제로 취급한다.

⚠ **다만 스와이프가 실제로 가능한지는 기기 OS 가 정한다**(2026-09-09 실기기 확인. 예전
서술은 축을 targetSdk 로 잡아 **틀렸다**):
- **13** — `setOngoing(true)` 가 FGS 알림 스와이프를 **막는다**(13 이 기본 허용으로 바꾼
  것을 되돌리는 공식 opt-out). 즉 그 기기에서는 삭제 인텐트가 **한 번도 발송되지 않는다**
  (테스트폰 SM-A325N 이 안드로이드 13 이다).
- **14+** — `ongoing` 은 스와이프를 못 막고 '모두 지우기' 만 막는다. 여기서만 삭제 인텐트가 산다.
- **≤12** — 확인 못 함.

⚠ **다시 울림에는 횟수 한도가 없다**(2026-09-09 지시로 설정 자체를 없앴다). 자동 재울림이
없으므로 그 숫자는 '사람이 버튼을 누를 수 있는 횟수' 였고 아무도 그렇게 읽지 않았다 —
한도에 닿으면 **'다시 울리기' 를 눌렀는데 알람이 꺼졌다.** 저장된 `snoozeRepeatLimit` 는
계약·동기화를 건드리지 않으려고 행에 남기되 **아무도 읽지 않는다.** 간격은 기본 5분이고
편집기에서 ＋/− 로 1분씩 조정한다(범위는 `SnoozeMinutes.range`).

단, **폴백 경로에는 삭제 인텐트를 걸지 않는다.** 포그라운드 서비스를 못 띄운 상황이라
`getService` 가 실패할 수 있고, 그 경로의 소리는 채널 사운드 1회성이라 '무한히 울림'
증상 자체가 없다.

## 3. 소리를 끄는 규칙 — **누가·언제** 끄는가

알람이 끝나는 길은 여럿이지만 **소리를 끄는 규칙은 하나**다.

1. **어떤 경로로 끝나든 소리를 먼저 끈다.** 끄기·다시 울림·목록에서 사라짐 — 전부.
2. **끄기 전에 소유권을 확인한다.** 지금 나는 소리가 *그 알람의* 것일 때만 끈다.
3. **대상을 모르면 끈다.** 소리가 남는 쪽이 더 나쁘다.

⚠ **'알람이 목록에서 사라졌을 때' 하나만 보면 안 된다.** 두 경우가 빠진다:
- **다시 울림**: 같은 id 로 카운트다운을 걸므로 알람이 목록에 **남는다**
- **주간 반복 알람의 끄기**: 반복은 OS 가 소유하므로 정지해도 목록에 **남는다**

둘 다 그 분기가 안 돌아 목소리가 계속 났다. 시스템 알럿은 이미 사라진 뒤라 화면에 멈출
버튼이 없어, 앱을 강제 종료해야 그쳤다(iOS, 2026-08-07 수정).

⚠ **소유권 확인 없이 끄면 반대 사고가 난다.** 사용자가 **다른** 알람을 지우면 그 알람도
'사라진 알람' 으로 들어오는데, 조건 없이 끄면 **지금 울리는 알람의 목소리가 끊긴다** —
알람은 계속 울리는데 목소리만 사라져 "왜 목소리가 안 나오지" 로 보인다.

## 4. 소리 규약

- **첫 샘플부터 제 크기.** 페이드인을 넣지 않는다 — TTS 한 문장이 램프 구간보다 짧아
  문장 전체가 작게 들린다.
- **반복도 커지지 않는다**(2026-08-27 실기기 로그로 확인). 목소리는 900ms 간격으로 계속
  반복되는데, 예전에는 **두 번째 재생부터** 음량 증폭기로 +6dB 를 걸었다(`gainMb=600`,
  삭제한 페이드인과 같은 커밋에서 근거 없이 들어왔다). 사용자가 맞춘 음량이 첫 회만
  지켜지고 그 뒤로 커지면 그건 그 음량이 아니다 — 공동 공간에 맞춰 작게 둔 알람이 두 번째
  문장부터 커진다. **처음부터 끝까지 같은 크기다.**
- **음량 슬라이더는 곱하지 않는다.** 목소리 슬라이더 = 목소리 게인, 알람음 슬라이더 =
  톤 게인. 곱하면 알람 음량을 낮출 때 못 줄이는 톤은 그대로인 채 목소리만 묻힌다.
- **미리듣기는 울림과 같은 스트림**이어야 한다(`USAGE_ALARM`). 기본값(`USAGE_MEDIA`)이면
  같은 설정인데 크기가 다르게 들려, 폰으로 검증하는 사람이 문제를 영영 못 잡는다.
  - ⚠ **맞추는 것은 스트림까지다 — 기기 볼륨은 건드리지 않는다.** 울림은 알람 스트림을
    중립(가득)으로 올렸다가 되돌리지만(`AlarmStreamVolume`), 미리듣기는 올리지 않는다.
    되돌릴 주인이 없어서다 — 남은 값을 되돌리는 `restoreIfLeftOver` 는 **울림 서비스가 뜰
    때만** 돌아서, 미리듣기 도중 화면을 벗어나거나 앱이 죽으면 사용자의 알람 볼륨이 다음
    울림까지 우리가 올린 값에 고정된다. 그래서 기기 알람 볼륨이 낮으면 미리듣기가 실제
    알람보다 작게 들리는 것은 **의도된 차이**다(같은 이유로 슬라이더를 스트림에 넘기지도
    않는다 — 아래 줄).
- ⚠ **스트림에 슬라이더를 넘기지 않는다** — 슬라이더는 플레이어 게인으로 이미 걸리므로
  스트림에도 넘기면 두 번 곱해져, 10% 알람이 낮은 기기 볼륨 위에서 ~1% 가 되어 안 들린다.
  스트림은 중립(가득)으로 올리고 크기는 게인 한 곳에서만 정한다.
- **안드로이드는 울릴 때 기기 알람 볼륨을 맞추고, 끝나면 되돌린다.** 되돌리기가 그
  클래스의 존재 이유다 — 올리기 **전에** 원래 값을 적어 두고, 프로세스가 죽어도 다음
  실행이 되돌린다.

## 5. 권한이 없으면 어떻게 되는가 — **안드로이드에서는 "안 울린다" 고 쓰지 말 것**

### 안드로이드 — 셋 중 무엇이 빠져도 **알람은 울린다**

안 울린다고 쓰면 사용자가 멀쩡히 울릴 알람을 없는 것으로 믿고 다른 알람을 또 맞춘다.

| 빠진 권한 | 실제 결과 | 어떻게 말하나 |
| --- | --- | --- |
| 알림 | 울린다. 울림 화면은 알림 권한과 무관하게 뜬다 — 알림·헤드업만 안 뜬다 | "알람 알림이 뜨지 않아요" |
| 정확한 알람 | 울리되 수 분 늦을 수 있다 | "제때 울리지 않을 수 있어요" |
| 잠금 화면 | 소리는 나되 잠금 화면을 못 덮는다 | "잠금 화면에 뜨지 않아요" |

그래서 **헤드라인은 언제나 남은 시간**이고, 무엇이 모자란지는 배너가 권한 이름과 함께
말한다.

### iOS — 권한이 없으면 **정말 안 울린다**

⚠ **이 한 줄 때문에 위 규칙을 iOS 에 그대로 적용하면 안 된다.** iOS 의 알람 권한은
AlarmKit 하나이고, 없으면 `AlarmManager.shared.schedule` 이 **실패해 예약 자체가 남지
않는다.** 우리가 대신 울려 줄 폴백 경로가 없다 — 울림 화면을 우리가 못 그리기 때문이다.

그래서 iOS 는 이때 **헤드라인이 남은 시간을 말하면 거짓말이 된다.** 권한이 없고 다음
알람이 있으면 헤드라인이 그 사실을 대신 말하고 경고색으로 그린다
(`NextAlarmHeadline.statusText` 의 `alarmPermissionMissing` 분기).

| | 안드로이드 | iOS |
| --- | --- | --- |
| 권한 없을 때 실제로 울리나 | **울린다**(방식만 달라짐) | **안 울린다**(예약 실패) |
| 헤드라인 | 언제나 남은 시간 | 권한이 없으면 그 사실 |
| 배너 | 무엇이 모자란지 권한 이름과 함께 | 같음 |

**두 문구를 서로 베끼지 말 것.** 안드로이드에 "울리지 않아요" 를 넣으면 거짓이고,
iOS 에서 그 문구를 지우면 안 울릴 알람을 울릴 것처럼 보여 준다.

## 6. iOS 는 이 판정을 하지 않는다 — 그리고 그게 맞다

위 1·2절은 **안드로이드의 규칙**이다. iOS 는 같은 결과를 다른 방식으로 낸다.

| 물음 | iOS 의 사실 | 근거 |
| --- | --- | --- |
| 전체화면/알림을 누가 고르나 | **시스템(AlarmKit)**. 앱은 판정하지 않는다 | 알람을 `AlarmManager.shared.schedule` 로 넘기면 ALERT UI 는 OS 가 그린다 |
| 화면을 벗어나면 꺼지나 | **아니다** — 시스템 alert 이라 앱에 `onStop` 이 없다 | 안드로이드 §2 의 '벗어남 = 해제' 는 우리가 화면을 그리기 때문에 가능하다 |
| 우리가 울림용 알림을 따로 띄우나 | **아니다** | `UNMutableNotificationContent` 는 `SocialNotificationTracker` 한 곳뿐이고, 그건 '가족 알람을 받았다' 안내 전용이다 |
| 알림을 스와이프하면 꺼지나 | **해당 없음** | 시스템 alert 은 스와이프로 지울 수 없다. 정지·스누즈 버튼으로만 끝난다 |
| 정지·스누즈는 어떻게 도나 | `StopAlarmIntent` / `SnoozeAlarmIntent`(LiveActivityIntent) → `AlarmManager.shared.stop` / `countdown`. **그 `countdown` 한 번이 유일한 재무장**이라(보조 버튼이 `.custom`) 실패하면 미루지 않고 `stop` 으로 끝낸다. 미루는 시간은 예약 때 구워진 행의 `snoozeMinutes` 뿐이다 | `Shared/AlarmIntents.swift`, `AlarmAppContext.rearmCountdown` |
| 포그라운드일 때 추가로 하는 것 | ring 시점 **경고 햅틱 1회**만 | 백그라운드·잠금화면에서는 시스템이 진동을 소유하므로 앱이 겹쳐 울리지 않게 `applicationState == .active` 로 가드 |

⚠ **그러니 iOS 에 '전체화면 vs 알림' 분기 코드를 만들지 말 것.** 만들어도 시스템이 이미
정한 뒤라 아무 효과가 없고, 두 개가 겹쳐 뜨는 위험만 생긴다.

## 7. 의도된 플랫폼 차이

| 항목 | 안드로이드 | iOS | 이유 |
| --- | --- | --- | --- |
| 울림 화면을 누가 그리나 | **우리** (`RingingActivity`) | **시스템** (AlarmKit ALERT UI) | AlarmKit 이 소유해 우리가 못 그린다 |
| 전체화면/알림 분기 | **판정하지 않는다** — §1 대로 **언제나 전체화면** | **판정하지 않는다** — 시스템이 정한다 | 안드로이드는 배너가 실제로 뜨는지 알 수 없어서, iOS 는 OS 소유라서. 결론이 같고 이유가 다르다 |
| 화면을 벗어나면 해제 | 있다(`onStop`) | **없다** | 시스템 alert 이라 벗어남을 알 수 없다 |
| 다시 울림 횟수 한도 | **없다**(무제한) | **없다**(무제한) | 자동 재울림이 없어 그 숫자는 '사람이 누를 수 있는 횟수' 였고, 아무도 그렇게 읽지 않았다 |
| 알람 음량 슬라이더 | 있다 | **없다** | AlarmKit 이 OS 톤을 소유해 제어 불가. 못 움직이는 컨트롤은 두지 않는다 |
| 정보량 보정 | — | alert 제목·Live Activity 에 **시각**을 넣는다 | 우리가 화면을 못 그리는 대신 |
