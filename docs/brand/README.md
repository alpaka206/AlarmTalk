# 브랜드 원본

여기 있는 두 장이 **원본**이고, 앱·랜딩·스토어의 아이콘/OG 이미지는 전부 여기서 파생한다.
로고를 바꾸면 이 파일을 갈아 끼우고 `python3 docs/brand/regenerate-icons.py` 를 다시 돌린다.

| 파일 | 크기 | 무엇 |
| --- | --- | --- |
| `app-icon-master.png` | 2048×2048 | **단색 `#0560E9` 배경 + 흰 시계 + 단색 파랑 파형**(풀블리드 정사각, 모서리 없음) |
| `og-master.png` | 3104×1312 | 딥네이비 배경 + 시계 + 워드마크 |

## 로고는 단색 파랑 하나다 (2026-09-29 통일)

두 폰의 홈 화면과 App Store 에 이미 나가 있던 **단색 파랑** 디자인으로 모든 로고를 맞췄다.
그 전에는 세 벌이 섞여 있었다:

- **단색 파랑** — iOS 앱 아이콘, 안드로이드 적응형 아이콘(홈 화면에 실제로 보이는 것).
- **그라데이션 파랑** — 옛 원본. 안드로이드 레거시 PNG 와 랜딩 아이콘이 여기서 나왔다.
- **청록 그라데이션 + 하트 모양 파형** — 더 옛날 로고. 알림 큰 아이콘(`ic_brand_logo`)이 이거였다.

새 원본은 옛 그라데이션 원본(`git show d0bb0e33:docs/brand/app-icon-master.png`)에서 시계만
뽑아(아래 '채널 최소값' 방법) `#0560E9` 위에 다시 얹은 것이다. 시계 크기·위치는 iOS
`AppIcon-1024.png` 를 재서 맞췄다 — 시계 bbox 의 긴 변(세로)이 캔버스의 **1532/2048(74.8%)**,
가운데 정렬. 이 원본을 1024 로 줄여 iOS 아이콘과 비교하면 평균 절대 차이가 **1.47/255**
이고, 차이는 전부 윤곽선 1~2px 에 있다(iOS 쪽이 288px 에서 확대한 것이라 윤곽이 무르다).

## 파생물

| 파생물 | 크기 | 만드는 법 | 사용자에게 보이는 시점 |
| --- | --- | --- | --- |
| 안드로이드 레거시 `mipmap-*/ic_launcher.png` | 48~192 | 원본을 그대로 축소 | 다음 안드로이드 릴리스(단 minSdk 26 이라 실제로는 거의 안 보이는 폴백) |
| 안드로이드 레거시 `mipmap-*/ic_launcher_round.png` | 48~192 | 원본 축소 + 원형 마스크 | 위와 같음 |
| 안드로이드 적응형 `mipmap-*/ic_launcher_foreground.png` | 108~432 | 원본에서 **시계만** 뽑아 캔버스 54% | 바뀌지 않음(이미 단색 디자인) |
| 안드로이드 테마 `mipmap-*/ic_launcher_monochrome.png` | 108~432 | 시계 실루엣(알파만) 54% | 바뀌지 않음 |
| 안드로이드 적응형 배경 `values/colors.xml` `ic_launcher_background` | — | 원본 배경색 `#0560E9` 그대로 | 바뀌지 않음 |
| 안드로이드 알림 큰 아이콘 `drawable-nodpi/ic_brand_logo.png` | 240 | 원본을 그대로 축소(정사각) | 다음 안드로이드 릴리스 |
| 랜딩 파비콘 `apps/landing/app/icon.png` | 512 | 원본 축소 | 다음 `main` 배포 |
| 랜딩 헤더·푸터 `apps/landing/public/brand-icon.png` | 256 | 원본 축소 | 다음 `main` 배포 |
| Play 등록정보 고해상도 아이콘 | 512 | 원본 축소(`--play <경로>`) — **저장소에 넣지 않는다** | Play 콘솔/API 로 따로 올린다 |
| iOS `AppIcon-1024.png` | 1024 | 적응형 전경의 보이는 영역(72dp)을 `#0560E9` 위에 합성 | 바뀌지 않음 — **스크립트가 만들지 않는다** |
| iOS `AppIcon-1024-dark.png` | 1024 | 딥네이비 `#0A1730` + 흰 실루엣(테마 아이콘에서) | 바뀌지 않음 — **스크립트가 만들지 않는다** |
| iOS `AppIcon-1024-tinted.png` | 1024 | 검정 + 흰 실루엣(테마 아이콘에서) | 바뀌지 않음 — **스크립트가 만들지 않는다** |
| 랜딩 OG `apps/landing/app/opengraph-image.png` | 1200×630 | `og-master.png` 를 cover 로 맞추고 가운데 자르기 | 바뀌지 않음 |

- **iOS 3종은 스크립트 밖이다.** 앱 아이콘은 IPA 에 실려 있어 바꾸면 앱 릴리스가 따라와야 한다 —
  아이콘만 바꾸려고 돌린 스크립트가 iOS 파일까지 조용히 바꾸면 안 된다. 지금 세 장은 새 원본과
  이미 같은 그림이다(위 1.47/255, dark·tinted 의 실루엣 bbox 도 원본과 1~2px 안).
- **적응형 전경·테마는 옛 그라데이션 원본에서 뽑은 것을 그대로 두었다.** 새 원본에서 다시 뽑아도
  평균 차이가 0.1/255 대라(시계 윤곽 반투명 픽셀만 다르다) 굳이 바꾸지 않았다. 스크립트를 다시
  돌리면 이 10장도 새로 쓰이는데, 눈으로는 차이가 없으니 그대로 커밋해도 된다.
- **OG 는 영향이 없다.** `og-master.png` 는 정사각 아이콘이 아니라 네이비 배경 위의 시계와
  워드마크라, 배경이 그라데이션이냐 단색이냐는 문제가 여기에는 없다.

## 다시 만들기

```bash
python3 docs/brand/regenerate-icons.py                         # 저장소 파생물 전부
python3 docs/brand/regenerate-icons.py --play /tmp/play-512.png  # + Play 등록정보 아이콘
```

스크립트가 하는 일과 이유(요약):

- **적응형 foreground 에 원본을 그대로 넣으면 안 된다.** 원본은 완성된 풀블리드 아이콘(파란 배경
  + 시계가 약 75%)이라, 108dp 중 가운데 72dp 만 보이는 규칙에 걸려 시계 본체가 잘리고 파형만
  남는다. 배경(파랑)은 background 레이어가 맡고 foreground 에는 **시계만** 넣는다.
- **시계 뽑기 = 채널 최소값.** 배경은 R 이 낮고 흰 시계는 R·G·B 가 모두 높다 → 세 채널의
  최소값이 곧 '흰 정도'. 70 이하 투명·150 이상 불투명으로 알파를 만든다. 시계 안 파형은
  배경이 비쳐 보이던 것이라 투명해지고, background 레이어의 같은 파랑이 그대로 채운다.
- **시계 bbox 를 108dp 캔버스의 54% 로.** 마스크 안에서 실제 보이는 건 가운데 72dp, 원형
  마스크 반지름은 36 이고, 종 끝이 bbox 반대각선의 92% 지점(중심에서 0.65×S)이라 S=54 면
  35.1 < 36 으로 **어떤 마스크에서도 안 잘린다**. 58 은 원형에서 종이 가장자리에 닿고, 50 은
  눈에 띄게 작다. (54/72 = 75% 라서 원본의 시계 크기(74.8%)와 거의 같은 비율로 보인다.)
- **테마 아이콘**(Android 13+)은 시스템이 **알파만 보고 단색으로 칠한다.** 컬러용(70~150)보다
  단단한 임계값(120~175)으로 잘라야 그림자가 안 번지고 실루엣이 깔끔하다. 크기·중심은 전경과
  같은 54% — 어긋나면 테마를 켤 때마다 아이콘이 튀어 보인다. `mipmap-anydpi-v26/ic_launcher{,_round}.xml`
  의 `<monochrome>` 으로 연결되고, 사용자가 테마 아이콘을 켰을 때만 쓰인다.

OG 이미지를 `[locale]/` 밖에 두는 이유: 이미지는 로케일별로 다르지 않고, `[locale]/`
아래에 두면 `output: export` 가 그 라우트에도 `generateStaticParams()` 를 요구해
빌드가 깨진다(동적 생성 라우트를 정적 파일로 바꾼 것도 같은 이유).

**적응형 아이콘 배경색**(`values/colors.xml` 의 `ic_launcher_background` = `#0560E9`)은 원본
배경색과 **같은 값이어야 한다** — 어긋나면 시계 안 파형만 다른 파랑으로 떠 보이고, 기기가
아이콘을 확대·시차 이동시킬 때 가장자리에도 드러난다.

레거시 `ic_launcher.png`·`ic_launcher_round.png` 는 풀블리드 원본 그대로 둔다 — minSdk 26
이라 모든 기기가 적응형을 쓰고, 이 PNG 들은 마스크·확대가 적용되지 않는 폴백이다.

`.webp` 로 바꾸지 않은 이유: 런처 아이콘은 몇 KB 수준이라 이득이 없고, PNG 가 모든
안드로이드 버전과 Next.js 정적 아이콘 규약에서 그대로 통한다.
