# 법무 / 개인정보 문서

알람톡(AlarmTalk)의 법무·개인정보 문서 모음이다. 한국 출시 기준이다. **처리방침·약관 본문은
Android·iOS 양쪽을 다룬다** — 정책 버전 5 에서 Apple 로그인·App Store 인앱결제·Apple 국외이전이
들어왔다. 다만 스토어 제출 체크리스트(`store-disclosures.ko.md`)는 아직 Google Play 기준이고,
앱 내 문구(`consent-and-permission-copy.ko.md`)도 Android 화면 기준으로 쓰여 있다.
법률 자문을 대체하지 않는다 — 출시 전 법무 검토를 권장한다.

## 이 문서들이 실제로 쓰이는 곳

- **`privacy-policy.ko.md` / `terms-of-service.ko.md` 는 랜딩 사이트가 빌드 시 그대로 읽어
  렌더한다**(`apps/landing/lib/legal-docs.ts` → `/ko/privacy`, `/ko/terms`).
  이 두 파일을 고치면 **공개 페이지 본문이 바뀐다.** 초안이 아니라 배포물로 다뤄야 한다.
- 나머지 4개는 앱·스토어 제출·내부 판단용 참고 문서이며 공개되지 않는다.

## 고칠 때 지킬 것

- **정책 버전은 코드가 단일 출처다.** `packages/backend/src/lib/consent.ts` 의
  `CURRENT_POLICY_VERSION` 과 처리방침·약관 머리말의 "정책 버전 / 최종 개정일" 을 함께 올린다.
  단, **공개되는 처리방침·약관 본문에는 상수명·파일 경로·테이블명 같은 구현 세부를 쓰지 않는다.**
  머리말은 `정책 버전: 4` 처럼 버전만 적고, 코드와의 동기화 규약은 이 문서에서 관리한다.
- ⚠ **번호를 새로 태우는 기준은 "그 버전이 이미 배포됐는가" 다**(2026-08-26 확정).
  버전을 올리는 이유는 딱 하나 — **앞 버전 본문에 동의한 사람**이 바뀐 본문에 동의한 것으로
  취급되는 것을 막기 위해서다. 그러니 판정도 그 하나로 한다:
  - `git show main:packages/backend/src/lib/consent.ts | grep CURRENT_POLICY_VERSION` 이
    **아직 그 번호가 아니면** 그 번호의 본문은 배포된 적이 없다 = 동의자가 0명이다.
    번호를 태우지 말고 **본문을 제자리에서 고친다**(머리말의 "최종 개정일" 만 갱신).
  - 이미 `main` 에 올라간 번호의 본문을 고칠 때는 **반드시** 새 번호를 태운다.
  실제 사례: 버전 5 는 `develop` 에만 있었고 prod 는 4 였다. 2026-08-24 보완분(원본 음성
  보관 기간 정정·국외 이전 필수 명시·환불 권리 명시)은 그래서 6 을 태우지 않고 5 본문에
  넣었다. 번호를 아끼려는 게 아니라, **보호할 동의자가 없는 번호를 태우면 그 번호를 담은
  앱이 스토어에 오를 때까지 신규 가입이 409 로 막히는 비용만 남기** 때문이다.
- **재동의는 내용이 바뀐 동의 유형만 받는다.** 정책 버전을 올려도 전 유형이 한꺼번에 만료되지
  않는다. 재동의 여부는 유형별 최소 정책 버전(`packages/backend/src/lib/consent.ts` 의
  `CONSENT_MIN_POLICY_VERSION`)으로 정하며, 개정이 **그 유형의 동의 내용을 실제로 바꿨을 때만**
  해당 유형의 최소 버전을 올린다. 수집·제공 범위를 줄이기만 한 축소 개정(예: 버전 4)은 기존
  동의 범위 안에 들어오므로 재동의 사유가 아니다 — 어느 유형의 최소 버전도 올리지 않는다.
  전 유형 만료는 실제 피해를 만든다: 모든 유형이 동시에 만료되면 이용자가 동의 화면 전체를
  다시 타고, 그 과정에서 켜 두었던 선택 동의(마케팅)가 초기화되어 꺼질 수 있다.
  같은 이유로 **클라이언트는 화면에 실제로 띄운 유형만 제출한다** — 띄우지 않은 유형의 기존
  동의 기록은 건드리지 않는다.
- **버전 8(2026-10-26) — v1.3 확대 개정.** 처리방침: 사용 기록 2판 칸(`docs/spec/usage-events.md` §7.5)·날짜 지정 알람과
  응원 방식·녹음 품질 판정·무료 체험 등 구독 조건·App Store 서버 알림(90일)·관리자 지급 기간·직접 입력 요청 식별자(2일)·보상형 광고(1.9,
  제공하는 경우)와 Google AdMob 위탁·국외 이전·Android 광고 ID 권한. 약관: 제4조 기능 목록(추가 음성팩은 제공하는 경우),
  제5조 날짜 지정 알람, 제10조 무료 체험 자동 결제·회사 지급·광고 보상, 제13조 음성팩 중단(제공하는 경우), 제15조 음성 이용 범위.
  조 번호는 다시 매기지 않았다.
  - **아침 소식은 8판에서 뺐다(2026-10-27, 오너 결정으로 기능 제거).** 8 이 아직 main 에 없어 제자리에서 고쳤다(위 번호 규칙).
    처리방침 1.8(관심 기업)은 「1.8 (삭제)」 로 자리만 남기고 1.9 번호를 그대로 둔다. 2장 목적·3장 보유 기간·14장 이력의 관심 기업,
    약관 제4조의 기능 줄과 제16조의 정보 성격 문단도 지웠다.
  - **서버 먼저**: `CURRENT_POLICY_VERSION = '8'`·`ACCEPTED_POLICY_VERSIONS = ['8', '7']` 이 main 에 먼저 나가고, 8판을 실은
    1.3 앱이 그 뒤에 게재된다. `'7'` 은 8판 앱을 `minSupported` 로 강제한 뒤 지운다.
  - **재동의는 아직 정하지 않았다**(어느 유형의 `CONSENT_MIN_POLICY_VERSION` 도 올리지 않음). 확대 개정이라 기준상 privacy 를 8 로
    올릴 대상이지만, 올리면 기존 사용자 전원이 처리방침을 다시 동의하는 화면을 본다. 올리지 않아도 사용 기록 2판 칸은 8판에
    동의한 사람(신규 가입·8판 앱의 재동의)부터만 저장되고, 광고는 이용자가 직접 고를 때만 처리된다.
    **올릴지는 오너·법무가 8판 앱 게재·옛 앱 차단 뒤에 정한다**(순서는 `docs/spec/consent.md`).
  - 보상형 광고 항목은 광고를 켜기 전에 넣었다 — 문서는 앱에 실리므로, 서버 스위치로 광고를 켤 때 앱을 다시 내지 않아도 되게
    했다. 맞춤 광고(광고 ID 사용) 여부와 위탁·제3자 제공 구분은 광고를 켜기 전에 법무 검토를 받는다.
  - 랜딩이 이 파일을 빌드 때 읽는다 — 랜딩을 배포하는 브랜치에 이 개정이 들어가는 순간 공개 페이지가 8판이 된다. 앱·서버
    출시와 시점을 맞춘다.
  - 2026-10-29 제자리 수정(main 전이라 번호를 새로 태우지 않는다): 계정 정보 필수 항목에서 **닉네임**, Apple 로그인 항목에서
    **최초 로그인 시 받은 이름**을 뺐다 — 닉네임 기능을 없애 더 수집하지 않는다(축소). 법무 검토본도 이 판으로 본다.
- **버전 7(2026-10-20) — 커플·가족 이용권 폐지에 따른 축소 개정.** 가족/파트너 그룹·초대 코드·음성 공유·가족
  알람(상대방 알람 설정) 내용을 처리방침·약관에서 걷어냈다. 버전 6 이 이미 `main` 에 있어 번호를 새로 태웠다(위
  규칙). 수집·제공 범위가 줄어드는 개정이라 **재동의는 없다** — 어느 유형의 `CONSENT_MIN_POLICY_VERSION` 도 올리지
  않는다(버전 4 와 같은 경우).
  - **조 번호는 다시 매기지 않는다.** 약관 제9조(가족/파트너 공유)는 「제9조 (삭제)」로 자리만 남기고, 처리방침 1.5 도
    같다. 다른 곳이 조 번호로 가리킨다 — 약관 제10조(`packages/backend/src/lib/app-version.ts`·iOS `PersonalPromo.swift`·
    `docs/spec/gates-and-overlays.md`), 제7조(앱 화면 문구·`docs/spec/voice-and-message.md`).
  - **서버 먼저**(버전 6 부터의 순서 — `CLAUDE.md` 「배포 / 환경」의 법무 문서 버전): `CURRENT_POLICY_VERSION = '7'`·
    `ACCEPTED_POLICY_VERSIONS = ['7', '6']` 을 `main` 에 먼저 내고, 7판을 실은 앱을 그 뒤에 게재한다. 옛 앱은 6 으로
    계속 받혔다. `'6'` 은 7판 앱(안드로이드 36·iOS 14)을 `minSupported` 로 강제한 뒤 2026-10-26 에 목록에서 지웠다
    (`docs/spec/plan-gates.md` 「커플·가족 이용권 — 폐지」의 강제 업데이트 순서).
  - 같은 개정에서 '목소리를 잃은 알람은 기본 알람음으로' 를 실제 동작(2026-09-29 부터 기본 목소리)에 맞게 고쳤다.
  - 본문의 새 문장에는 줄표(—)를 쓰지 않는다 — 공개 페이지와 앱의 동의 화면에 그대로 보인다.
- **가입 화면에는 필수 4종과 선택 2종을 구분해 노출한다.** 필수는 만 14세·이용약관·
  개인정보 처리방침·국외 이전이고, 음성 생체정보와 마케팅은 선택이다. 음성 생체정보를
  거절한 사용자는 목소리를 만들려는 시점에만 다시 묻는다. 미들웨어의 앱 전체 하드 게이트와
  음성/TTS 라우트의 민감 동의 게이트는 별도다. 근거는
  [`compliance-notes.ko.md`](compliance-notes.ko.md) §1·§8, 화면 카피는
  [`consent-and-permission-copy.ko.md`](consent-and-permission-copy.ko.md)를 따른다.
- **실제 코드가 하는 일만 적는다.** 수집하지 않는 항목, 붙어 있지 않은 수탁사, 없는 기능을
  처리방침·약관에 적으면 그 자체가 허위 고지다. 고치기 전에 백엔드/앱 코드로 교차검증할 것.
- 사업자 정보(베일런·대표 김규원·사업자등록번호·주소·연락처)의 기준은
  [`privacy-policy.ko.md`](privacy-policy.ko.md) 머리말이다. 다른 문서는 이를 따라간다.
