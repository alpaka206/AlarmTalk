## 구현·운영 메모 (이 문안을 "실제로 참"이 되게 하려면)

> 출시 전 prod는 미배포·DB 초기화 예정이고 현재 마케팅 발송은 일어나지 않으므로 **현 시점 위반은 없다.** 단, 실제로 마케팅을 보내기 시작하기 전에 아래가 갖춰져야 위 문안의 모든 조항이 사실이 된다.

1. **설정 화면 철회 토글 부재** — `SettingsScreen.kt`에 마케팅/야간 수신 토글이 없고, 가입 후 `marketing` 동의를 `agreed=0`으로 재기록하는 클라 경로(`POST /user/consents`)도 없음. → 토글 + 재기록 경로 구현. (미구현 시 §5의 "앱 설정 철회"를 이메일 문의로만 한정해야 함)
2. **야간 별도 동의 미구현** — `CONSENT_TYPES`에 야간 유형 없음, `ConsentScreen.kt`는 `marketing` 단일 체크박스, 발송 시 시간대 게이트 없음. → `marketing_night`(가칭) 동의 유형 + 체크박스 + 발송 시간대 게이트 구현. (미구현 시 §3을 삭제하거나, 마케팅 발송 자체를 주간으로만 제한)
3. **마케팅 발송 경로 자체가 없음** — 푸시(`fcm.ts`)·이메일(`email-verification.ts`) 채널은 있으나 "광고 목적 발송" 코드가 없음. → 발송 시 `(광고)` 제목 프리픽스 + 전송자 명칭·연락처 + 수신거부 안내를 코드로 강제.
4. **수집 항목 정합** — 본 문안의 수집 항목은 현재 실제 수집분(이메일·FCM 토큰·닉네임·식별자·동의이력)에 맞췄음. **발송/열람 추적(open tracking) 기반 "맞춤형 광고"는 현재 미수집**이므로 문안에서 제외함. 추후 맞춤형 추천을 하려면 반응 이력 수집 + 별도 고지 + on/off가 필요.
5. **사업자 정보 확정** — 상호/대표/등록번호/주소/연락처는 `privacy-policy.ko.md`와 일치(검증됨).
