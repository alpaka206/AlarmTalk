## 왜 반복되는가

- **한 규칙을 적용해야 할 경로가 나뉘어 있었다.** 보류 복구의 users.plan 재계산을 고쳐도
  구독 응답·초대 사용·초대 발급이 예전 조건을 쓰면 기능이 엇갈린다. 이전 수정에서 연결된
  경로까지 확인하지 못한 부분이다. 이번 조회는 기존 선택 함수를 직접 재사용하고,
  초대의 발급·재발급·사용과 iOS의 일괄·단건을 함께 수정했다.
- **기존 누락도 새로 발견되고 있다.** iOS의 소유자 없는 후보 필터와 음성 가족 알람의
  유료 게이트 누락은 #740 수정 전 코드에도 있었다. 리뷰가 추가됐다는 사실만으로 직전
  커밋이 모두 새로 만든 버그라고 볼 수는 없다.
- **테스트의 빈틈이 있었다.** 이전 경합 테스트는 같은 계정의 편집·취소를, 복구 테스트는
  users.plan 변경을 주로 확인했다. 계정 전환과 실제 구독 응답·초대 소비 경로를 빠뜨렸다.
  CI는 작성된 사례를 검증하므로 그 범위 밖의 권한 누락까지 보장하지 않는다.
- 확인 시 #730은 839개 파일·추가 140,095줄·삭제 11,911줄의 통합 PR이다. 이 범위에서는
  후속 리뷰마다 다른 경로가 드러날 수 있어 남은 리뷰 횟수나 무결함을 확정할 수 없다.
  앞선 #740의 작성자 지적 두 건은 오탐이었지만, 이번 4건은 실제 동작 문제다.

이번 범위는 지적된 권한 경로와 직접 연결된 호출부·응답·회귀 사례다. 로컬 빌드·테스트는
실행하지 않았으며 CI 완료를 기다리지 않는다. 새 마이그레이션이나 배포는 없다.
실기기의 계정 전환 및 스토어 보류·복구 검증은 릴리스 단계에 남는다.
