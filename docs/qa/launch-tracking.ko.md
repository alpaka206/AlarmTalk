## 🔴 출시 막는 항목 (Blocker)

### L1 — 음성 제공자 법무·배선 정합성
런타임에서 생체 음성(클론)을 처리하는 경로는 **ElevenLabs**로 정한다.
- 개인정보처리방침·약관·동의·스토어 라벨은 실제로 음성을 보내는 제공자, 처리 국가, 하위수탁자와 **일치**해야 한다.
- 국외이전 동의는 음성 AI 처리와 동적 문구/번역 경로에서 계속 서버가 강제한다.
- 법무 문서 정합성은 법무 문서 정리 작업에서 함께 다룬다.

## 🟠 미해결 (High~Medium — 출시 전 처리 권장)

### M1 — 음성 클론 업로드에 바이트 크기 상한이 없음
음성 클론 등록 경로는 길이(초)만 검증하고 **파일 바이트 크기 상한이 없다**.
같은 계열의 다른 업로드 경로(일반 업로드 25MiB, 알람 원본 5MiB)는 상한이 있는데 클론만 빠져 있다.
- 클라이언트가 길이는 정상으로 신고하면서 큰 파일을 올리면 워커 메모리에 통째로 적재되고 그대로 유료 제공자로 전달된다(메모리 한도·비용 위험).
- 권장: 클론 경로에도 동일한 바이트 상한(예: 25MiB)을 두고 초과 시 413으로 거절.

### M2 — 화자분리(diarize) 경로가 유료 확인 전에 본문을 메모리에 적재
화자분리 엔드포인트는 **유료 플랜 확인보다 먼저** 업로드 본문을 전부 읽는다. 또 이 엔드포인트 자체엔 MIME/크기 검증이 없다(일반 업로드 경로에만 있음).
- 무료/남용 호출자가 큰 본문을 반복 전송하면 거절될 요청에도 메모리를 쓴다.
- 권장: 유료 확인을 버퍼 읽기 앞으로 옮기고, 일반 업로드와 동일한 MIME·크기 검증 추가.

### M3 — 서버 간 결제 알림(웹훅) 미비로 환불·취소 반영 지연
구글 RTDN 경로는 들어와 있으나, 애플 App Store Server Notifications V2 기반의 권한 갱신이 갖춰져 있지 않다.
- 환불/차지백/스토어측 취소/유예기간 전환이 클라이언트 재확인이나 만료 크론 전까지 반영되지 않는다(환불 후에도 만료 전까지 유료 기능 유지 등).
- 권장: 애플 서명 검증 웹훅을 붙여 권한 부여/회수를 알림 기반으로 구동. 그전까지는 "환불·취소 반영 지연"을 알려진 제약으로 문서화.

## 🟡 미해결 (Low — 가능하면 정리)

### N1 — 구글 로그인 nonce/리플레이 검사 없음
애플 로그인은 nonce를 검증하지만, 구글 id_token 검증에는 nonce 검사가 없다. id_token 재전송(리플레이) 방어가 한 겹 부족하다.

### N2 — 결제 웹훅(RTDN) 인증 토큰이 쿼리스트링에 있음
RTDN 검증 토큰이 헤더가 아니라 `?token=` 쿼리로 들어온다. 오류 시 모니터링(요청 URL)에 토큰이 함께 캡처될 수 있으니, 헤더로 옮기거나 URL 스크럽을 적용하는 게 좋다.

### N3 — 애플 거래 JWS 서명체인 미검증
애플 거래 JWS 페이로드를 서명/인증서 체인(x5c) 검증 없이 디코드만 한다. 현재는 애플 TLS 엔드포인트 응답에만 쓰여 당장의 위험은 낮지만, 향후 클라이언트/S2S 입력에 재사용되면 위조 거래를 수용할 수 있다. 서명 검증을 붙여두면 출처와 무관하게 안전.

### N4 — 음성 프로필 삭제 시 외부 제공자 클론 삭제 실패가 조용히 무시됨
음성 프로필 삭제에서 외부(ElevenLabs) 클론 삭제가 실패해도 빈 catch로 삼키고 로컬만 삭제한다. 키 미설정/일시 5xx면 제공자 측 클론이 남아 슬롯 쿼터를 잠식한다(재시도 큐/마커 없음). 실패 시 재시도 큐 적재 또는 최소한 로깅이 필요.

### N5 — 제공자(ElevenLabs) 오류 원문이 클라이언트 응답에 반사됨
TTS·음성 클론 실패 시 제공자 오류 메시지(`detail`)가 그대로 클라이언트로 내려간다. 제공자 내부 식별자·쿼터 메시지 등이 노출될 수 있으니, 안정적인 에러코드로 매핑하고 원문은 서버 로그에만 남기는 게 좋다.

### N6 — TTS 출력 포맷을 제공자에 명시하지 않고 기본값에 의존
TTS 요청에서 출력 포맷을 명시하지 않고 `Accept` 헤더만 보내며 제공자 기본값에 의존한다. 캐시 키·포맷 컬럼은 'mp3'를 가정하므로, 제공자가 기본 포맷을 바꾸면 저장 바이트와 메타가 어긋날 수 있다. 출력 포맷을 명시하고 캐시 키에 포함하면 장기 캐시가 안전.

### N7 — 선물 수락이 비트랜잭션 + pending 가드 없음
선물 수락에서 상태 UPDATE에 `status='pending'` 조건과 rowsAffected 확인이 없고, message_library에 (user_id, message_id) 유니크 제약도 없다. 동시 수락 시 라이브러리에 중복 복사본이 생길 수 있다. 트랜잭션 + 조건부 UPDATE + 유니크 인덱스(INSERT OR IGNORE)로 정리 권장.

### N8 — 이메일 코드 재전송 쿨다운 없음
인증 코드 재요청에 per-email 쿨다운이 없어 이메일 폭탄 여지가 있다. (전역 레이트리밋은 있으나 코드 재발송 자체에 대한 제한은 없음.)

## ⚪ 운영·문서·앱 위생 (확인/결정 필요)

- **시크릿 로테이션**: 작업 트리의 dev 시크릿 파일(미커밋이지만 실키)은 출시 전 전량 로테이션하고 wrangler secrets로 옮긴다. 시크릿 값·경로는 여기 적지 않는다. *사용자 작업 필요.*
- **개인정보처리방침 버전(재동의)**: 정책 버전을 올려야 기존 사용자에게 재동의 경로가 뜬다. ElevenLabs 기준 수탁사 고지 개정과 함께 버전 bump 필요(법무 문서 작업과 연동).
- **법무 고지 정합성**: Vertex(알람문구·사주 데이터 국외이전), 사주 항목(성별/생년월일/출생시각) 명시, FCM/PortOne 수탁사 고지 등은 법무 문서 정리 작업에서 코드 동작과 대조해 마무리.

## ✅ 대조 결과: 해결로 확인된 항목 (참고)

코드에서 직접 확인해 **해결**로 분류한 것들(추적 종료):

**백엔드 보안/인증**
- OAuth `email_verified` 강제(구글·애플) + 애플 클라 이메일 fallback 제거 → 계정연동 탈취 차단.
- 토큰 폐기(token_epoch) + 로그아웃 엔드포인트 + 폐기 토큰 거부(TOKEN_REVOKED). raw 제공자 토큰 직접 수용 제거(앱 JWT 전용).
- note 오디오 로더 하드닝 — 임의 https 프록시 차단 + r2 키 소유자 네임스페이스 강제(교차 테넌트 읽기·SSRF 차단).
- 알람 PATCH의 message_id/voice_profile_id 소유권 재검증(IDOR 차단).
- 서버측 동의 강제 미들웨어(일반 필수 동의 403 게이트) + 음성 클론에 voice_biometric, 국외이전 경로에 overseas_transfer 동의 강제.
- 로그인 실패 응답 일원화 + 미존재 계정 더미 bcrypt(계정 열거·타이밍 오라클 제거).
- init-db/seed 전 환경에서 시크릿 헤더 요구(미인증 파괴/비용 표면 제거).
- auth 전용 엄격 레이트리밋(별도 버킷).
- pending_deletion 상태 확인 불가 시 fail-closed로 전환.
- AUTH 401 경로 로그를 구조화 로깅으로 교체(토큰 원문·구성 단서 미노출).
- 계정삭제 userPk 조회에 apple_id 포함(레거시 애플 계정 자식 PII 고아화 해소).
- `GET /user/search`가 타인 이메일을 반환하지 않음(null 처리).
- `email_verification_codes` 만료분 크론 정리 추가.
- 결제 스텁(checkout/change-plan)·test-codes가 production에서 항상 비활성 + 발급자 하드코딩 개인 이메일 제거.
- 바우처 사용 시 멤버 있는 소유 그룹 자동 해체 방지 가드(OWNS_ACTIVE_GROUP).
- 가족 초대 좌석 초과 TOCTOU 차단(원자적 조건부 INSERT).

**음성 파일 라이프사이클**
- 메시지 삭제 시 R2 오브젝트 삭제 큐 적재.
- raw-alarms 업로드 추적 테이블 + 미연결 클립 TTL 정리 + 계정삭제 정리.
- 알람 PATCH로 녹음 교체 시 이전 R2 정리.
- TTL 정리 시 messages.audio_url 댕글링 포인터 NULL 처리 + 활성 알람이 쓰는 TTS 보존.

**일일 TTS 한도 레이스(B/HIGH)** — 일일 TTS 횟수 제한 자체가 폐지됨(컬럼 제거). 레이스 조건은 더 이상 존재하지 않음.

**안드로이드 동작**
- 알람 발화 FGS 백그라운드 시작 크래시 가드(try/catch + 풀스크린 알림 폴백).
- 시간대/DST 변경 시 재스케줄 리시버(ACTION_TIMEZONE_CHANGED/TIME_CHANGED).
- 동적 보이스 새로고침 워커 스케줄링 연결(데드코드 해소).
- Geocoder 오류 시 코루틴 행 수정.
- 캡처 방지(FLAG_SECURE) 적용(dev 빌드는 의도적으로 해제).
- UI/접근성 다수(코치마크 maxWidth, 시간피커 폰트스케일, AlarmRow 말줄임+접근가능 삭제, 온보딩 \n 제거, LazyColumn key, base64 IO 디스패처, 데드코드 제거 등).
