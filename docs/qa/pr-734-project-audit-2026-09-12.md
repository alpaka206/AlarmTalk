### 2026-09-13 추가 리뷰 1건 (`aaac1fb8` 대상) — 인증 전 본문 선행 버퍼링

- [비인증 요청의 본문을 먼저 모으는 문제](https://github.com/alpaka206/AlarmTalk/pull/734#discussion_r3996820625):
  실제 누락. 앞선 헤더 위조 방어는 실제 바이트 상한만 확인하고, 전역 미들웨어가 인증 전에
  전체 본문을 모은다는 실행 순서와 메모리 비용을 놓쳤다. 비인증 동시 업로드도 최대 25 MiB씩
  보관했고 정상 업로드에는 multipart/파일 파싱 외에 미들웨어 사본까지 남았다.
- 전체 `chunks` 버퍼를 없애고, 하위 소비자의 read마다 한 청크만 전달하는 제한 스트림으로
  교체했다(`highWaterMark: 0`). 헤더가 이미 상한을 넘으면 읽지 않고 413, 인증/라우팅에서
  끝나면 본문을 읽거나 비우지 않고 취소한다. 느리거나 실패한 취소가 응답을 막지 않는다.
- 헤더 누락·위조와 무관하게 실제 읽기에서 초과 청크를 차단한다. 파서/라우트 catch나
  전역 오류 처리가 400/500으로 바꿔도 마지막에 기존 `413 REQUEST_BODY_TOO_LARGE`를
  유지한다. 요청별 초과 표시는 `logRouteError`의 서버 장애 오인·Sentry 중복 보고를 막고,
  최종 413은 기존 `errorCodeMiddleware`가 기록한다. 다른 스트림 오류는 그대로 보고한다.

`bodyLimit.test.ts`에 실제 인증 미들웨어의 무소비 거절, 느림/실패 취소, 청크별 수요 읽기,
정확한 25 MiB·JSON·multipart 전달, catch/onError 뒤 413과 경보 구분의 회귀 사례를 작성했다.
기존 과대 본문 테스트도 「라우트 진입 전 전량 검사」가 아닌 「소비 중 차단, 파싱 후 처리 금지」
계약으로 수정했다. 규칙과 구현 지도는 `docs/spec/error-codes.md`에 기록했다.
**빌드·테스트·CI·별도 자체 리뷰는 실행하지 않았다.** Workers 런타임의 메모리/동시 요청
실측을 완료한 것으로 주장하지 않으며, 실행은 `develop → main` 단계에 남긴다.

  취소했다. 쓰기 트랜잭션 안에서 같은 사용자의 다른 활성 구독에 연결된 스토어 증빙을
  확인하고, 남아 있으면 교체를 재시도 가능한 오류로 거절한다. 같은 스토어·해지 예약·지난
  로컬 만료도 예외가 아니며 72시간 강제 만료도 허용하지 않는다. 조회 중 새로 생긴 구독과
  증빙도 이 검사에 걸린다. 별도 권위 정합화로 다른 구독을 종료한 뒤에는 교체할 수 있다.
  교체 없는 갱신과 스토어 증빙 없는 로컬 이용권의 기존 교체는 유지한다.
- [독립 유료 멤버의 잘못된 삭제 예고](https://github.com/alpaka206/AlarmTalk/pull/734#discussion_r3996901163):
  앞선 고아 등급 복구는 자기 호출부에서만 유료 멤버의 보관 유예를 해제했다. 공통
  `disbandOwnedPlanGroup`은 여전히 전원에게 예약해 일반 스토어 전환에서 거짓 예고가 나갔다.
  남은 plan 재계산 후 유료이면 기존 유예까지 지우고, 실제 무료 멤버만 예약하도록 공통
  함수로 옮겼다. 고아 복구 호출부의 중복 보정은 제거했다. 유료 멤버도 그룹 접근 변경은
  동기화해야 하므로 `plan_changed` 대상에는 그대로 남는다.

`billing-reconciliation.test.ts`에 실제 DB 회귀 사례 20건을 추가 작성했다:
다른 행 증빙 보호 8건·72시간 우회 방지·동시 추가 2건·별도 종료 뒤 재시도 2건·정상 갱신/로컬

스펙·구현 지도·릴리스 핸드오프도 갱신했다. **빌드·테스트·CI·자체 추가 리뷰는 실행하지

## 함께 고친 결함과 중복 제거

- 결제 전 조회·만료 크론·RTDN 종료/보류는 `billing-reconciliation.ts`를 공유한다.
  스토어 I/O는 쓰기 락 밖에서 하고, 구독·영수증이 바뀌었으면 트랜잭션 안에서 거절한다.
- 보류 때 그룹을 보존하고, 회복 때 멤버 권한·기간과 삭제 유예를 같은 트랜잭션으로 복구한다.
  소유자의 유효 구독이 남아 있으면 멤버만 독립적으로 만료시키지 않는다.
- 구독 스냅샷은 `user_plan`·구독·갱신 스토어를 같은 DB 읽기 트랜잭션에서 구성한다.
  양 앱은 오래된 세션/세대의 응답을 버리고, Play는 SDK의 비동기 제품 조회 이후에도 재검사한다.
- Apple 유예 만료는 `gracePeriodExpiresDate`를 사용한다. 알 수 없는 상태/조회 실패는
  종료로 추정하지 않는다. 만료 크론의 기존 72시간 조회 장애 유예는 유지한다.
- 결제일은 Apple `purchaseDate`, Play 최신 성공 주문의 실제 처리 시각을 사용한다.
  연장·유예·중복 전송을 새 결제로 추정하지 않는다. 예약 교체의 아직 소유하지 않은 상품도 배제한다.
- 선물의 실제 구매일을 저장하고, 탈퇴 시 한 구독에 연결된 여러 증빙을 각각 보존한다.
  토큰 없는 기존 Apple 구독의 바인딩 조회도 저장 키인 originalTransactionId를 사용한다.
- 환불 조회 중 같은 체인의 새 갱신이 반영되면 옛 종료 응답으로 현재 구독/그룹을 지우지 않는다.
- JWT 만료/주체 형식과 정확한 만료 경계를 검사한다. 서버 JWT 설정 누락은 401이 아닌 503이며,
  iOS는 인증 토큰 없이 보낸 요청의 401로 현재 세션을 종료하지 않는다.
- Content-Length 누락/조작과 무관하게 실제 바디 스트림에 25 MiB 상한을 적용한다.
  프로필 PATCH의 null/배열/원시 JSON은 500 대신 400으로 거절한다.
- Android 알림 권한 예외 처리를 기존 runCatching과 동일한 명시적 catch로 표현했다.
  울림 예약·시간 계산·재생·로컬 권한 판정의 동작은 바꾸지 않았다.
- 취약한 baseline-browser-mapping, @humanfs/node, Wrangler/Miniflare 간접 의존성을
  기존 호환 범위 내에서 갱신했다. CI에 high 이상 의존성 감사와 Android release lint를 추가했다.

중복된 SQL 큐 기반 Apple 만료/보류 테스트는 실제 마이그레이션을 적용한 독립 파일 SQLite
통합 테스트로 이관했다. 트랜잭션 롤백, 조회 중 갱신/교체, 멤버 독립 구독, 72시간 경계,
반복 알림 방지, RTDN 실제 HTTP 라우트도 검증한다.
